# HnS 번역 기준과 작업 범위

친구(저장소 소유자)가 2026-10-12에 정한 기준이다. 원문은 [`FRIEND_REPLY_2026-10-12.md`](../friend-handoff/FRIEND_REPLY_2026-10-12.md) 1·2절과 4절 7번이다. 번역 우선순위는 [`FRIEND_REQUEST_2026-10-10.md`](../friend-handoff/FRIEND_REQUEST_2026-10-10.md) 1절에서 처음 정했다. 이 문서와 친구 원문이 다르면 원문을 따르고, 새 지시가 오면 이 문서를 고친다.

요약:

- **전투·시스템 텍스트**는 최신 본가의 공식 한국어 원문을 줄바꿈까지 그대로 쓴다. "HnS 관례"를 이유로 바꾸지 않는다.
- **NPC 대화·포켓기어 텍스트**는 HGSS 공식 한국어 원문을 보존한다(최신 작품 우선순위를 적용하지 않음).
- **작업 범위:** Claude는 1.17.1까지 포트하면서 새로 생기는 배틀 메시지만 번역한다. 기존 HnS 텍스트는 영문이 남아 있어도 친구가 요청하지 않으면 번역·수정하지 않는다. 기존 텍스트 한글화는 친구가 로컬에서 한다.

## 1. 어느 규칙을 적용하나

| 텍스트 | 기준 | 이 문서 |
| --- | --- | --- |
| 전투 메시지, 기술·특성·도구 설명, 메뉴, 시스템 메시지 | 최신 공식 한국어(2절 우선순위) | 3절 |
| NPC 대화, 포켓기어 텍스트 | HGSS 공식 한국어 보존 | 4절 |
| 공식 게임에 대응하는 문장이 없는 HnS 고유 텍스트 | 최신 공식 용어·문체로 자체 번역(공식과 구분해 기록) | 3절 5번, 4절 5번 |

## 2. 공식 한국어 번역 우선순위

**Champions > PLZA > SV > PLA > BDSP > SWSH > LGPE > USUM > SM > ORAS > XY > BW2 > BW > HGSS > Pt > DP > pokeemerald-kr**

- 같은 기능이나 상황에 대응하는 공식 한국어 표현이 있을 때 적용한다.
- pokeemerald-kr은 팬 번역이다. 공식 번역과 섞어 부르지 않는다.
- NPC 대화·포켓기어 텍스트에는 적용하지 않는다(4절).

## 3. 전투·시스템 텍스트 규칙

1. **Poké Corpus의 공식 한국어 원문을 먼저 확인한다.** 같은 상황의 문장이 여러 작품에 있으면 2절 우선순위가 가장 높은 작품의 문장을 쓴다.
2. **표현·조사·어미·띄어쓰기·문장부호·줄바꿈을 원문 그대로 둔다.** 단어가 같아도 줄바꿈이 다르면 공식 원문과 같다고 보지 않는다.
3. **"HnS 관례"를 이유로 공식 번역을 고치지 않는다.** 포켓몬 이름 뒤에서 줄을 바꾸거나 주어와 서술어를 다른 줄로 나누는 식의 규칙을 만들지 않는다.
4. **화면 폭 때문에 공식 줄바꿈을 지킬 수 없으면 먼저 보고한다.** 다시 줄을 바꾸지 말고, 측정한 폭과 넘치는 부분, 수정안을 함께 알린다. 친구가 정하기 전에는 적용하지 않는다.
5. **공식 게임에 대응하는 문장이 없는 HnS 고유 텍스트만 자체 번역한다.** 최신 공식 게임의 용어와 문체를 따르고, 결과 문서에서 공식 번역과 자체 번역을 구분해 적는다.
6. **기존 텍스트 변수는 유지한다.** 포켓몬 이름·상대 구분·조사 토큰(`{B_SCR_NAME_WITH_PREFIX}`, `{B_TXT_EUNNEUN}` 등)을 그대로 쓰고, HnS 변수 치환 때문에 문법이나 의미가 달라지지 않는지 확인한다.

작업 순서: **공식 원문 확인 → 실제 상황 대조 → HnS 텍스트 변수 적용 → 출력 폭 검증.**

### 3.1 포트에서 새 배틀 메시지를 옮기는 절차

1. **원문 찾기.** Poké Corpus는 커밋을 고정한 raw URL로 받는다.
   `https://raw.githubusercontent.com/abcboy101/poke-corpus/5d1da078d70dea5c9feaaba7575626eab4f10a08/corpus/<게임>/<언어>_<파트>.txt`
   (예: `ScarletViolet/ko_common.txt`, `LegendsZA/ko_common.txt`). 같은 게임의 `en_<파트>.txt`와 `ko_<파트>.txt`는 줄 번호가 같다. upstream 영문에서 짧은 구절로 `en` 파일을 찾고 같은 줄의 `ko`를 읽는다. 영문 줄은 중간에 `\r\n`으로 끊겨 있을 수 있으므로 긴 문장 전체로 찾지 않는다. 우선순위가 높은 작품부터 찾고, 같은 문장이 여러 작품에 있으면 모두 적는다.
2. **변수 대응.** 원문의 `[VAR 0102(…)]`(포켓몬 이름) 등은 상황에 맞는 HnS 토큰으로, `[VAR 1900(0001)]` 같은 조사 변수는 HnS 조사 토큰(`{B_TXT_EUNNEUN}` 등)으로 옮긴다. 원문의 `\n`은 HnS 문자열에서도 같은 자리의 `\n`이다. 다른 제어 기호(`\r`, `\c` 등)는 HnS 대응을 정하기 전에 보고한다.
3. **실제 상황 대조.** upstream 배틀 스크립트에서 그 문장이 나오는 상황이 원문 문장의 상황과 같은지 본다(예: 같은 날씨가 이미 있을 때의 별도 문장인지).
4. **폭 검증.** 문장이 표시되는 창의 실제 글꼴로 줄마다 폭을 잰다. 배틀 메시지 창은 `FONT_NORMAL`, 폭 208 px이다(한글 8 px, 공백 3 px, `!` 4 px, 라틴 문자는 `src/fonts.c` `gFontNormalLatinGlyphWidths`). 이름이 들어가는 줄은 가장 넓은 이름(라틴 12바이트 약 72 px, 한글 6자 48 px)과 `상대 `·`야생 ` 접두어까지 넣어 잰다. 넘치면 4번 규칙대로 보고한다.
5. **기록.** 결과 문서에 공식 출처(작품·파일·줄 번호, Poké Corpus 커밋)와 폭 측정값을 적는다. 공식 대응 문장이 없어 자체 번역했다면 "자체 번역"과 근거(참고한 공식 용어)를 적는다. 출력이 바뀌면 `BATTLE_MESSAGE_OUTPUT_CHANGES.md`에도 적는다.

사례: seq 281 #10395의 진홍빛고동·하드론엔진 문장 4개는 단어·문장부호가 SV 원문과 같았지만 이름 뒤에서 줄을 바꿔 공식 줄바꿈과 달랐다. 친구 지적으로 `600646ca43`에서 공식 줄바꿈으로 고쳤다(재확인 55).

## 4. NPC 대화·포켓기어 텍스트 예외

HnS는 HGSS를 기반으로 하므로 스토리와 등장인물의 대사는 HGSS 원작의 공식 한국어 텍스트를 최대한 보존한다.

1. HGSS에 같은 NPC 대사나 포켓기어 문장이 있으면 **HGSS 공식 한국어 원문을 최우선**으로 쓴다.
2. 최신 작품에 비슷한 표현이 있어도 HGSS 대사를 그 표현으로 바꾸지 않는다.
3. 최신 게임의 문장부호 관례에 맞춰 **문장 끝에 온점을 더하는 정도의 최소 수정만 허용**한다. 모든 문장에 일괄로 온점을 더하라는 뜻은 아니다.
4. 인물별 말투·어휘·문장 구성·대사 흐름을 유지한다. 자연스럽게 만든다는 이유로 의역하거나 다시 쓰지 않는다.
5. HGSS에 없는 HnS 추가 NPC·신규 이벤트 대사는 HnS의 의도를 보존하면서 HGSS 문체에 맞게 번역한다.
6. 화면 폭·줄바꿈 문제는 실제 표시를 확인하고 필요한 최소한만 조정한다.

**이 규칙은 친구가 로컬에서 NPC·포켓기어를 번역할 때의 기준이다. Claude는 친구가 요청하기 전에는 NPC 대화·포켓기어 텍스트를 번역하지 않는다(5절).**

## 5. 작업 범위 — 기존 텍스트 임의 수정 금지

기존 HnS 텍스트의 한글화는 친구가 로컬에서 진행한다. 위 규칙은 앞으로 번역할 때의 기준이지 기존 텍스트를 다시 번역·정리하라는 뜻이 아니다.

| Claude가 하는 것 | Claude가 하지 않는 것 |
| --- | --- |
| pokeemerald-expansion **1.17.1까지 포트하면서 새로 추가되는 배틀 메시지**를 2·3절 기준으로 번역 | 기존 HnS 텍스트 번역·수정(**영문이 남아 있어도**) |
| 친구가 **명시적으로 요청한 번역**(예: 트레이너 클래스명·트레이너 이름·인물명) | NPC 대화·포켓기어 텍스트 번역 |
| 기존 번역의 오류·개선점을 찾으면 **보고만** | 찾은 오류를 요청 없이 직접 고치기 |
| 포트에 필요한 코드·텍스트만 최소 범위로 변경 | 기존 텍스트를 upstream 영문 원문이나 다른 번역으로 덮어쓰기 |

1. 포트 중 기존 텍스트 파일(`src/battle_message.c`, `src/strings.c`, `data/text/`, 맵 스크립트 등)을 고쳐야 하면 새 기능에 필요한 줄만 바꾸고 나머지 번역은 그대로 둔다. upstream이 기존 문자열의 영문을 바꾼 hunk는 HnS 한글을 유지한다. 토큰·인자가 바뀌어 HnS 한글도 고쳐야 하는 경우만 최소로 고치고 결과 문서에 적는다.
2. 친구의 로컬 번역 작업과 충돌할 수 있는 변경(친구가 작업 중일 수 있는 텍스트 파일을 넓게 고치는 PR, 문자열 위치·이름을 옮기는 리팩터 등)은 **적용 전에 친구에게 알린다.**
3. 이미 알려진 기존 텍스트 문제(예: 재확인 9·10·11·42·47)는 기록만 하고, 친구가 요청하면 고친다.
4. 친구가 요청해 이미 진행한 번역(트레이너 클래스명·이름·인물명 등)은 기존 결정대로 이어서 한다.
5. **해석(친구 확인 후보):** 포트로 새로 들어오는 **배틀 메시지가 아닌** 텍스트(메뉴·시스템·디버그·도구 설명 등)는 원문에 정해져 있지 않다. 친구 확인 전까지는 영문 그대로 두고 결과 문서에 목록으로 보고한다.
