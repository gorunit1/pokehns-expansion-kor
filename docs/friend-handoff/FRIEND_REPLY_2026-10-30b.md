## 2. 매지컬리프와 엔진 버전은 현재 반영 상태 유지

매지컬리프는 `860292b1`의 **잎 이동 22프레임·타격 전 `delay 30`·`target_both=FALSE`**를 유지해 줘.

## 3. 이미 전달한 결정은 적용 상태를 정리해 줘

다음 항목들은 이미 답해서 전달한 내용이야. 네 현재 코드에서 반영됐는지 확인하고 **적용 완료·구현 대기·내 실기 대기**로 나눠 줘.

- **3b 춤추기:** 내가 요청해 반영한 현재 수정을 유지해 줘. 위기회피·도망태세로 들어온 춤추기가 해당 춤을 따라 하는 동작을 되돌리는 b·b2는 적용하지 말아 줘.
- **23:** `B_MULTI_HALF_TEAMS FALSE` 유지. 배틀타워 멀티 UI와 동시 발견 트레이너의 파티는 내가 실기로 확인할 항목이야.
- **70(a):** 알 보존·보충 후 회복 수정 진행. 알이 파티 제한을 꽉 채우면 마지막 알을 PC로 옮기는 방향이야. **PC까지 꽉 찬 경우에는 알을 삭제하지 말고 추가 설계를 먼저 보고해 줘.**
- **70(b):** 파트너 배틀의 기존 기절 포켓몬 삭제 면제는 유지하고, 보충 과정에서 원래 포켓몬이 덮어써지는 문제만 막아 줘.
- **71:** 빈 트레이너 슬라이드 표 축소는 이미 승인했어. 등록된 전투 중 대사가 없는 현재 동작을 보존하면서 표와 조회 코드를 함께 정리하고, 테스트용 슬라이드 처리는 유지해 줘. 배틀 전 머그샷이나 승리·패배 대사를 제거하는 작업은 아니야.
- **72:** Set Ability의 파티 선택 취소 후 범위를 벗어난 접근을 막는 방어 코드도 승인했어. 현재 소스 문맥에 맞춰 반영해 줘.
- **82:** Gen9 필드 날씨 규칙은 지원하되 HnS에서는 그 제한을 켜지 않고 기존 날씨 기술·특성 동작을 유지하는 방향이야. 앞서 요청한 HnS 전용 설정 구분이 반영됐는지 확인해 줘. 아직 `GEN_8` 값만 유지 중이라면 현재 구현과 필요한 최소 변경을 설명해 줘.

이미 반영했다면 커밋·검증 근거를 연결해 주고, 미반영이라면 승인된 범위에서 진행해 줘. 이미 전달한 결정을 다시 사용자 답변 대기로 두지는 말아 줘.

## 5. 선택 버그 수정 결과와 남은 위험

8건 중 실제 적용 4건, 미영향 2건, HnS에서 이미 방지한 2건으로 구분한 보고 확인했어.

이번 작업은 1.17.1 기반의 선택 버그 수정이며, 1.17.2·upcoming 전체 이식은 아니라는 범위도 유지해 줘.

2대1 HP 박스, 신비의부적·플라워베일 아래 구슬 발동과 면역 보존, 난기류 문장, 훔친 야생 도구의 포획·도주·KO 경로는 내가 새 ROM에서 확인할게. 네 자동 검사와 코드 대조는 별도 검증 근거로 보존하겠어.

**가방이 꽉 찼을 때 훔친 도구가 사라지는 위험은 별도 미해결 항목으로 남겨 줘.** 기존에도 있던 문제라는 점과 이번에 지급 시점이 배틀 종료로 바뀐 점을 구분해 줘.

가방 추가에 실패해도 도구를 보존할 수 있는 처리안을 먼저 제안해 줘. 그 설계를 보기 전에 가방 규칙이나 포획 개체의 도구 귀속을 추가로 바꾸지는 말아 줘.

가로채기로 멀리짖기를 가져올 때 오류 화면이 뜨는 문제도 기존 결정대로 미해결 목록에 유지해 줘.

## 6. 기존 한글 문구 확인 및 필요한 수정

아래 7개는 이번에 내가 명시적으로 확인·수정을 요청하는 범위야. 다른 기존 문장이나 NPC·포켓기어 대사까지 범위를 넓히지는 말아 줘.

**6-3은 공식 대응 문장이 확인될 때만 번역하고, 6-4는 현재 번역 상태에서 문제가 재현될 때만 수정 여부를 검토해 줘.**

공식 문장은 기존 우선순위에 따라 단어·조사·문장부호·줄바꿈까지 대조하고, 자체 번역은 공식 원문과 구분해서 기록해 줘.

### 6-1. 재확인 9 — 텔레키네시스 조사

`STRINGID_HURLEDINTOTHEAIR`의 이름 뒤 고정된 `는`을 `{B_TXT_EUNNEUN}`으로 바꿔 줘.

```c
"{B_DEF_NAME_WITH_PREFIX}{B_TXT_EUNNEUN}\n높이 뛰어올랐다!"
```

'마자용은', '피카츄는'처럼 받침에 맞게 나와야 해.

우선 조사 오류를 고치고, 본문을 바꾸려면 텔레키네시스의 공식 대응 문장인지 먼저 확인해 줘. 같은 문장이 다른 기술에 쓰인다는 것만으로 텔레키네시스 공식 원문으로 확정하지 말아 줘.

### 6-2. 재확인 10 — 로부터/으로부터

`STRINGID_CLOAKEDINAHARSHLIGHT`는 다음처럼 수정해 줘.

```c
"{B_ATK_NAME_WITH_PREFIX}{B_TXT_EU}로부터\n눈부신 빛이 넘쳐흐른다!"
```

마자용으로부터·피카츄로부터·마릴로부터가 각각 맞게 나와야 해. 기존 `{B_TXT_EU}`의 ㄹ 받침 예외를 활용하고, 조사 처리 규칙을 중복 구현할 필요는 없어.

공식 대조 근거는 Poké Corpus `57e5078`의 PLZA `ko_common.txt` 6095행과 SV 8157행이야. 본문과 줄바꿈은 보존해 줘.

### 6-3. 재확인 10c — 거다이맥스 시작 영문

`STRINGID_TIMETOGIGANTAMAX`의 `Time to Gigantamax!`는 해당 분기에 정확히 대응하는 공식 한국어 문장이 확인될 때만 번역해 줘.

**공식 대응 문장이 없다면 영문 그대로 유지해 줘. 자체 번역은 하지 말아 줘.**

소드실드의 특정 트레이너 개별 대사를 공통 시스템 문장으로 대신 사용하지도 말아 줘. 확인한 자료와 공식 대응 문장 확인 여부만 기록하면 돼.

이 항목 때문에 거다이맥스나 AI 기믹 설정을 켤 필요는 없어.

### 6-4. 재확인 10g — 현재 클래스명 번역에서 문제가 남는지 확인

클래스명 번역은 이미 적용되어 있어. 따라서 과거 영문 클래스명에서 발견한 공백 깨짐을 현재도 그대로 발생하는 문제로 간주하지 말아 줘.

현재 사용하는 클래스 표와 번역 적용 범위를 확인하고, 특히 공백이 있는 **'포켓몬 브리더', '엘리트 트레이너', '새 조련사'** 및 클래스명과 트레이너 이름을 합치는 문장에서 문제가 남는지 확인해 줘.

**현재 한글화된 사용 경로에서 문제가 재현되지 않는다면 공통 문자열 처리 코드는 수정할 필요 없어.** 기존 항목에는 클래스명 번역 이후 확인한 범위와 결과를 남겨 줘.

미번역 클래스명이 남아 있다면 실제 HnS·시설·통신에서 쓰이는지 구분해 줘. 이 확인을 이유로 미사용 클래스명까지 추가 번역할 필요는 없어.

문제가 재현된다면 해당 경로의 최소 수정안을 먼저 설명해 줘. `0x39`와 한글의 충돌 가능성만으로 전체 문자표나 공통 한글 판정을 변경하지 말아 줘.

네 코드·자동 검사 결과와 내 QA 환경의 실제 화면 확인은 구분해서 기록하자.

### 6-5. 재확인 11 — 멸망의바디 영문

`STRINGID_PKMNSWILLPERISHIN3TURNS`의 영문을 다음 공식 문장으로 바꿔 줘.

```text
두 포켓몬 모두 3턴 후에 쓰러져 버린다!
```

Poké Corpus `57e5078`의 PLZA `ko_common.txt` 6876행과 SV 8930행에서 확인한 문장이야.

이 문자열은 `BattleScript_PerishBodyActivates`에서 실제 호출하므로, 사용되지 않는다는 기존 주석도 현재 코드에 맞게 정리해 줘.

특성 팝업·발동 조건·멸망 카운트·기절 처리는 변경하지 말아 줘.

### 6-6. 재확인 42 — 볼 바꾸기 성공 문장

HnS 고유 볼 교체 기능의 성공 문장은 다음 자체 번역으로 적용해 줘.

```c
"{STR_VAR_1}의 볼을\n{STR_VAR_2}{K_EU}로 바꿨다!{PAUSE_UNTIL_PRESS}"
```

`STR_VAR_1`은 포켓몬의 닉네임, `STR_VAR_2`는 실제 사용한 볼 이름을 사용해 줘. 일반 메뉴용 `{K_EU}`로 '으로/로'를 처리하고, 성공 후 입력 대기도 유지해 줘.

이미 수정한 GS볼 이름·실제 사용 도구 참조·볼 1개 소비·다른 도구 수량 보존은 그대로 유지해 줘. 같은 볼이라 교체할 수 없는 경우의 기존 처리도 건드리지 말아 줘.

### 6-7. 재확인 47 — 불사르기 문장

`STRINGID_INCINERATEBURN`의 도구 이름 뒤 `{B_TXT_EUNNEUN}`은 목적격 조사 `{B_TXT_EULREUL}`로 고쳐 줘.

'고스트주얼은 녹여 버렸다'가 아니라 '고스트주얼을 녹여 버렸다'가 되어야 해.

최종 출력은 공식 우선순위에 맞춰 공격자·도구 보유자·도구 이름이 들어가는 문장 구조도 대조해 줘. Poké Corpus `57e5078`의 Champions `ko_ms.txt` 1496~1499행 구조를 참고해 줘.

현재 별도로 있는 `STRINGID_PKMNITEMMELTED`와의 관계도 확인하되, 공격자·대상·효과 대상 버퍼를 확인하지 않고 문자열 ID만 교체하거나 합치지는 말아 줘.

공식 줄바꿈을 HnS 제어 코드에 맞게 옮기고 메시지창 폭을 실측해 줘. 넘친다면 임의로 문장을 줄이거나 줄바꿈을 바꾸기 전에 알려 줘.

효과가 막힌 쥬얼에도 문장이 나오는 문제는 별도의 동작 문제로 기록하고, 이번 문구 수정만으로 도구 효과 판정까지 변경하지 말아 줘.

## 7. 검증·완료 보고 및 실기 기준

이번에 받은 네 환경의 실기용 ROM 정보는 다음으로 기록했어.

- 게임 코드: `4c447b25`
- ROM SHA1: `c5132aa0808210d23b4ab52d4cc2e3d13adfe080`
- 사용 용량: 32,978,292 B
- 빌드: 클라우드 `make hns -j8`, GCC 13.2.1
- README 변경은 ROM에 영향 없음

내 QA 환경에서 실행하거나 다시 빌드한 ROM은 별도의 기준 커밋·해시·빌드 환경으로 관리할게. 내가 아직 전달하지 않은 실기 결과를 네 자동 검사 결과로 대신 완료 처리하지 말아 줘.

실제 게임 코드를 수정한 항목은 네 작업환경에서 빌드와 관련 자동 테스트·한글 회귀·세이브 정적 비교를 진행해 줘.

문구 수정은 받침 있음·없음·ㄹ, 플레이어·상대 진영, 긴 이름의 폭을 구분해서 확인해 줘. 공통 문자열 처리 코드를 실제로 수정하게 된다면 관련 인트로·승패·교체 문장도 회귀 확인해 줘.

출력이 의도적으로 바뀐 테스트는 근거와 기대값 변경 이유를 남기고, 실행하지 않은 검사는 PASS로 기록하지 말아 줘.
