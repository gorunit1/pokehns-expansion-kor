# HnS 1.17.0 full-sync — 후속 검증 결정 및 추가 수정 요청

기존 full-sync 작업을 계속 진행하면서, 재확인 66~70의 후속 결정과 새로 확인한 디버그 오류, 타이틀 화면 그래픽, 금액 표시 문제를 함께 반영해 줘.

이번 요청에는 기존 동작을 유지할 항목, 분석만 진행할 항목, 실제 코드 수정을 요청하는 항목이 섞여 있어. 각 항목의 처리 범위를 구분하고, **새로운 수정은 작업별로 구분해서 커밋해 줘.**

필요한 그래픽 ZIP과 금액 표시 패치는 별도로 첨부할게. 빌드와 Windows mGBA 실기 검사는 내가 직접 진행하겠어.

## 1. 재확인 69 — 하드 너즐록 미러 패배 시 세이브 삭제 유지

**재확인 69의 ①번, 기존 하드 너즐록 삭제 규칙을 그대로 유지하는 것으로 결정할게.**

너즐록 설정의 `OFF → 이지 → 노말 → 하드` 중 하드 모드는 메뉴에 “배틀에서 지면 저장 데이터도 삭제됩니다”라고 명시돼 있어.

따라서 일반 미러 배틀에서도 패배했다면, 원래 파티가 살아 있는 상태로 복구됐더라도 게임 오버 및 세이브 삭제를 유지하는 것이 맞다고 판단했어.

- 일반·이지 너즐록: 재확인 67의 원래 파티 보호 장치 유지
- 하드 너즐록: `CB2_WhiteOut`의 기존 세이브 삭제 및 리셋 유지
- 하드의 기권·미러 재전 패배: 기존 종료 정책 유지
- 너즐록 종료 상태, 시설 및 명시적 화이트아웃 면제: 기존 예외 유지

재확인 67의 보호 장치는 `DoWhiteOut()`에 있고, 하드 삭제는 그보다 먼저 실행된다고 했으니 보호 장치를 제거할 필요는 없어.

**미러 패배만 하드 너즐록의 세이브 삭제에서 제외하는 새로운 예외는 만들지 말아 줘.**

재확인 69에는 이 결정을 기록해 줘.

실제 삭제 검사는 원본 세이브와 완전히 분리한 일회용 사본으로 진행할게. 하드 모드에서는 세이브가 정상적으로 삭제되는 것이 기대 결과야.

## 2. 재확인 70 — 알 소실 및 보충 포켓몬 회복 누락

재확인 70의 두 문제도 확인했어.

- 전멸 후 알만 남았을 때 보충 과정에서 1번 칸의 알이 덮어써지거나 파티가 지워지는 문제
- 빈 파티에 박스 포켓몬을 보충한 뒤 파티 마릿수가 갱신되지 않아 회복이 누락되는 문제

이 문제는 재확인 67의 보호 장치가 새로 만든 회귀가 아니라 **기존 너즐록 보충 문제**로 별도 기록해 줘.

아직 수정하지 말고 보류 상태로 유지하자. 다만 현재 동작을 의도된 규칙으로 확정하는 것은 아니야.

후속 수정을 검토할 수 있도록 다음을 분석해 줘.

1. 알이 있는 파티에서 빈칸을 사용하거나 위치를 정리해 보충할 수 있는지
2. 박스 후보가 없을 때도 기존 알을 보존할 수 있는지
3. 보충 뒤 파티 마릿수와 회복 처리를 어디에서 갱신해야 하는지
4. 일반·이지 너즐록, 파티 제한, 박스 후보 선택에 미치는 영향

구체적인 수정안과 검증 범위를 먼저 알려 줘. 재확인 69의 하드 삭제 유지 결정과 묶어서 너즐록 규칙을 변경하지는 말아 줘.

## 6. 디버그 친밀도·포켓러스 선택 슬롯 오류 수정

이 항목은 첫 번째 답장에서 코드 확인을 요청했던 문제인데, 이후 Windows mGBA 자동 실기에서 **실제 FAIL 2개가 재현됐고 원인 분석까지 완료했어.**

따라서 기존의 조사 요청을 다음 수정 요청으로 갱신할게.

### 실제 확인된 오류

- `b22-06`: 친밀도 설정에서 세 번째 포켓몬을 선택해도 첫 번째 포켓몬이 수정됨
- `b22-05`: 포켓러스 설정에서 세 번째 포켓몬을 선택해도 첫 번째 포켓몬이 수정됨

선택 번호 전달과 Task 초기화는 정상인데, Main 함수에서 선택한 슬롯 번호를 0으로 덮어쓰는 것이 공통 원인이야.

### 수정 요청

`src/debug.c`의 다음 두 함수에서 각각 `gTasks[taskId].tPartyId = 0;` 한 줄씩 삭제해 줘.

- `DebugNativeStep_Party_SetFriendshipMain`
- `DebugNativeStep_Party_SetPokerusMain`

그 외 선택·저장 구조는 변경하지 않아도 돼.

이번 문제는 묶음 22 이전에도 존재했던 코드이므로 이번 full-sync가 새로 만든 회귀로 분류하지 말아 줘. 이전의 `tStrain` 데이터 칸 충돌 수정과도 별개야.

원인 분석은 `ROOT_CAUSE_B22.md`에 정리되어 있어.

### Set Ability 취소 처리 검토

추가로 `Set Ability` 디버그 기능은 포켓몬 선택을 취소할 때 유효 범위 검사가 없어 범위 밖 메모리를 읽을 가능성이 있어.

이 문제는 아직 실제 mGBA FAIL로 확인되지 않았으니 앞의 두 오류와 분리해서 처리해 줘.

우선 취소 경로를 검토하고, 필요한 최소 방어 처리 방법을 확인해서 알려 줘. 불필요한 구조 변경은 하지 말아 줘.

### 검사 계획

두 슬롯 오류의 수정은 현재 full-sync 작업에 포함해 줘.

새 ROM을 전달받으면 내가 Windows Codex 자동 QA로 다음을 확인할게.

- 첫째·셋째·마지막 슬롯 선택
- 선택 취소 및 복귀
- 선택한 포켓몬만 변경되는지
- 다른 포켓몬의 데이터 보존
- 기존 자동 QA 17개 회귀 검사

이 자동 QA 17개는 앞서 설명한 `test/hns_nuzlocke_whiteout.c`의 너즐록 보존 테스트 17개와 별개로 관리할게.

## 7. HnS 타이틀 화면 최종 v3 반영

HnS 타이틀 화면의 「포켓몬스터」 및 「하트앤소울」 로고를 최종 수정했어.

첨부한 `HnS_title_pixel_exact_v3.zip`을 기준으로 `pokehns-expansion-kor` 브랜치에 반영해 줘.

별도 테스트 클론 `pokehns-test`에서 최종 v3 출력이 정상인 것을 직접 확인했어.

### 7-1. 그래픽 파일 교체

ZIP의 다음 3개 파일을 교체해 줘.

- `graphics/title_screen/hns/pokemon_logo.png`
- `graphics/title_screen/hns/pokemon_logo.pal`
- `graphics/title_screen/hns/emerald_version.png`

`pokemon_logo.png`는 마지막으로 수정한 최종 로고이며, 이전에 누락됐던 상단 검은 윤곽선도 복원했어. 반드시 v3 파일을 기준으로 적용해 줘.

최종 로고 좌표는 다음과 같아.

- 포켓몬스터 로고: X=43, Y=10
- 하트앤소울 로고: X=133, Y=45

기존 그래픽 구조는 유지해 줘.

- 포켓몬스터: 256×64 BG2 그래픽
- 하트앤소울: 64×32 OBJ 스프라이트 2개

### 7-2. `src/title_screen.c` 수정

다음 좌표와 팔레트 로딩을 적용해 줘.

| 항목 | 최종 값 |
|---|---|
| `VERSION_BANNER_LEFT_X` | 165 |
| `VERSION_BANNER_RIGHT_X` | 229 |
| `VERSION_BANNER_Y_GOAL` | 61 |
| 배너 시작 Y | 기존 2 유지 |
| HnS BG 팔레트 로딩 | `16 * PLTT_SIZE_4BPP` |
| HnS 배너 OBJ 팔레트 로딩 | `9 * PLTT_SIZE_4BPP` |

HnS 전용 변경은 `#if IS_HNS`로 분리해서 일반 에메랄드에는 영향을 주지 않도록 해 줘.

### 7-3. `graphics_file_rules.mk` 수정

HnS 팔레트 변환 규칙을 다음과 같이 변경해 줘.

- `hns/pokemon_logo.gbapal`: `-num_colors 240`
- `hns/emerald_version.gbapal`: `-num_colors 144`

일반 에메랄드의 규칙은 유지해 줘.

### 7-4. `rayquaza.bin` 수정

`graphics/title_screen/hns/rayquaza.bin`에서 실제 사용되는 타일 640개의 팔레트 뱅크를 14에서 15로 변경해 줘.

- 타일 번호 유지
- 배치 및 플립 정보 유지
- 미사용 패딩 영역 유지
- `rayquaza.png`는 수정하지 않음

하트앤소울 로고 아래쪽의 하늘색 경계는 원래 HnS 배경이므로 그대로 유지하기로 결정했어.

### 7-5. 기존 애니메이션 유지

로고 위치 변경으로 기존 타이틀 애니메이션이 깨지지 않게 다음을 유지해 줘.

- BG2 초기 X 오프셋 `-29`
- BG2 초기 Y 오프셋 `-32` → 최종 `0`
- 로고 반짝임 시작 Y `68`
- 기존 로고 반짝임 및 이동 애니메이션
- 하트앤소울 배너 Y=2 → Y=61 이동
- PRESS START 및 버전 표시 점멸

정지 화면뿐 아니라 등장 애니메이션에서도 최종 위치에 자연스럽게 연결되도록 해 줘.

ZIP 안에는 내가 테스트 클론에서 사용했던 수정 스크립트도 들어 있어. 테스트 클론 전용으로 제작한 것이므로 **원격 저장소에서 스크립트를 직접 실행하지 말고 수정 내용만 참고해서 반영해 줘.**

타이틀 화면 관련 커밋에는 이 항목의 변경만 포함해 줘. 빌드 및 mGBA 검사는 내가 직접 하겠어.

## 8. 게임코너 및 공통 금액 표시 잘림 수정

게임코너에서 동전을 구매할 때 왼쪽 상단 용돈 표시창의 `원` 글자가 오른쪽으로 잘리는 문제를 발견했어.

현재 `src/money.c`의 금액 출력 로직이 영문 기준 고정 좌표와 공백을 사용하고 있어서, 한글 `원`이 추가되면 표시창 내부 폭을 초과하는 것으로 보여.

수정 참고용으로 `hns_money_width_fix.patch`를 첨부할게.

패치를 무조건 그대로 적용하지 말고 현재 HnS 코드와 대조해서 필요한 부분을 보완해 줘.

### 수정 요구 사항

1. 금액이 출력되는 각 창의 실제 내부 폭을 기준으로 숫자와 `원`을 오른쪽 정렬해 줘.
2. 기존 고정 좌표와 불필요한 공백 대신 문자열의 실제 픽셀 너비를 계산해 줘.
3. 금액이 길어질 경우 필요한 범위에서 좁은 글꼴을 사용하되 숫자와 `원`이 모두 표시되도록 해 줘.
4. 금액이 변경될 때 이전 숫자가 남지 않도록 기존 출력 영역을 적절히 지워 줘.
5. 게임코너뿐 아니라 상점의 소지금·구매 금액, 가방의 판매 금액 등 공통 금액 출력 함수를 사용하는 화면에도 적용해 줘.
6. 기존 UI 테두리, 화폐 표기, 다른 텍스트 및 수량 표시가 영향을 받지 않게 해 줘.

공통 함수를 수정할 때는 각 화면의 창 폭이 서로 다를 수 있다는 점을 고려해서 처리해 줘.

**기존 UI 레이아웃 전체를 변경하지 말고, 금액 문자열의 폭과 출력 위치를 바로잡는 최소 수정으로 해결해 줘.**

이 항목도 실기 검사는 내가 직접 진행할게.

## 9. 기존 full-sync 진행 및 호환성 유지

위 요청 사항을 반영하면서 full-sync는 기존 순서대로 계속 진행해 줘.

첫 번째 답장 기준으로는 seq 352부터 진행을 요청했지만, 그 이후 이미 처리한 작업이 있다면 되돌리지 말고 **현재 실제 진행 지점부터 이어 가 줘.**

선반영한 PR은 원래 순서에서 중복 적용하지 말아 줘.

다음 사항은 계속 유지해야 해.

- 기존 한국어 번역 및 UI
- 메가진화 특성 할당
- 파동의방호
- HnS 고유 기능
- AI 교체 무한 루프 방지 가드
- 기존 세이브 데이터 호환성
- 기존 너즐록 보호 장치 및 확정한 난이도별 규칙
- 일반 에메랄드와 HnS 전용 코드의 구분

기존 기준 기록은 다음과 같아.

- 문서·테스트 HEAD: `1a4d9543`
- 게임 코드 기준: `4ae4d7e1`
- 친구 ROM SHA1: `008d5029554bcae3c4f943edf585bbec2a8a9e1a`
- ROM 사용량: 32,787,012 B
- 기존 빌드 환경: 클라우드 GCC 13.2.1

이는 당시의 기준값이며 현재 HEAD나 최신 ROM 해시라는 의미는 아니야.

게임 코드가 변경되는 다음 보고에는 최신 기준 커밋, 포함된 변경 사항, 검증 결과를 함께 알려 줘.
