# HnS full-sync 묶음 18·19 확인 및 미러 챌린지 패배 처리 결정

묶음 18·19, 아테나 멀티 승리 후 화이트아웃 수정, 도감 설명과 방벽 후속 수정 보고 모두 확인했어.

이미 반영한 수정은 보고한 방향으로 유지해 줘. 보류했던 **#10568의 `battle_setup.c` 수정도 적용하는 것으로 결정할게.** 아래에 이유와 검증 범위를 정리했어. 사용자 mGBA 실기는 별도로 새 ROM에서 진행하겠어.

## 1. 아테나 멀티 승리 후 화이트아웃 — #10814 / 32a5fd5a

이번 문제는 배틀에서 실제로 패배한 것이 아니라, **승리 결과가 배틀 종료 처리 중 다른 값으로 덮여서 이벤트가 패배 쪽으로 진행한 회귀**로 이해했어.

`AreMultiPartiesFullTeams()`가 반쪽 팀 여부를 확인하면서 `VAR_RESULT`에 0 또는 1을 쓰는데, 아테나+조무래기 전투에서는 승리값 1이 반쪽 팀 판정값 0으로 바뀌어 퇴각 대사 대신 화이트아웃 분기로 들어가는 구조였어.

따라서 `SPECIAL_BATTLE_MULTI` 종료 처리에서 `gSpecialVar_Result = gBattleOutcome;`로 실제 승패를 다시 전달하는 #10814의 한 줄 수정은 유지해 줘. seq 542의 선반영 기록도 유지하고, 해당 순서에서는 중복 적용하지 말아 줘.

다음 조건을 확인해 줘.

- 아테나+조무래기에게 승리하면 퇴각 대사와 이벤트가 정상 진행되고 화이트아웃되지 않는지
- 패배하면 승리 대사나 후속 진행 없이 기존 정책대로 화이트아웃되는지
- 승리 뒤 목호·로켓단 NPC·문·발전기 후속 이벤트와 진행 상태가 정상적으로 이어지는지
- 선택해 참가한 포켓몬과 참가하지 않은 원래 파티의 복구가 유지되는지
- 같은 종료 처리를 사용하는 다른 멀티에서도 실제 승패가 그대로 전달되는지

이전 ROM에서 이 장면을 지난 세이브가 있다면 사본으로 재도전 가능 여부와 후속 진행을 확인할게. **화이트아웃됐다는 사실만으로 세이브가 영구적으로 손상됐다고 단정하지는 말자.** 진행이 막힌 사례가 확인되면 당시 ROM·승패·진행 상태·관련 플래그를 기록하고 원인을 확인해 줘. 복구를 위해 플래그를 임의로 초기화하는 작업은 별도로 판단하자.

## 2. 질문 — 미러 챌린지 패배 / 재확인 35 / #10568

**보류했던 #10568의 `battle_setup.c` 수정을 적용해 줘. 일반 트레이너전에서 미러 챌린지로 패배하면 화이트아웃되고, 승리 보상이나 스토리 진행을 받지 않는 것으로 정할게.**

확인한 기존 처리에서는 일반 미러 배틀이 끝나면 원래 파티를 복구하고, 그 뒤에 살아 있는 포켓몬이 있는지 다시 검사해. 그래서 복사한 파티가 패배했어도 복구된 원래 파티가 살아 있으면 화이트아웃을 건너뛰고 이벤트로 돌아갈 수 있어.

비상 체육관처럼 배틀 뒤에 별도의 승패 확인 없이 배지·기술머신·진행 플래그를 처리하는 이벤트에서는, 이 경로로 패배 후에도 승리 보상이 지급될 가능성이 있어. 실제 실기 재현은 아직 하지 않았지만, 코드상 경로는 확인했어.

이 동작은 포트 이전 HnS에도 있었으므로 **이번 full-sync가 새로 만든 회귀라고 기록하면 안 돼.** 또한 공식 기능 설명과 최초 미러 구현 이력에서 ‘패배해도 배지나 보상을 받도록 의도했다’는 명시적인 근거는 찾지 못했어. 개발자가 인정한 버그라고 단정하지도 말아 줘.

이번 결정은 **우리 한글패치 프로젝트에서 미러 챌린지의 패배 처리를 실제 승패에 맞추기로 선택한 기존 동작 변경**으로 기록해 줘. 개발자 의도 확인을 적용의 선행 조건으로 두지는 않을게.

수정 범위는 실제 패배 결과에 따라 종료 처리를 하는 부분이야. 복구된 파티가 살아 있다는 이유로 패배가 승리 후 진행으로 이어지지 않도록 해 줘.

다음 기존 규칙은 보존해 줘.

- 일반 미러의 원래 파티 복구
- 도둑미러의 배틀 후 파티 보유 규칙
- 명시적인 화이트아웃 면제와 시설·초기 라이벌 등의 예외
- 목호 반쪽 팀 멀티와 배틀타워 NPC 멀티에 따로 정해 둔 HnS 패배 처리
- 일반 모드의 정상 승패 처리와 기존 세이브 구조

검증은 다음처럼 승리·패배·예외를 나눠서 진행해 줘.

1. 배지 미취득 상태에서 일반 미러로 비상에게 패배하면 화이트아웃되고, 배지·기술머신·배지 수·승리 진행 플래그가 지급되거나 증가하지 않는지
2. 같은 조건에서 승리하면 기존 보상과 스토리 진행이 정상 처리되는지
3. 승리와 패배 모두 원래 파티·도구가 기존 복구 규칙대로 처리되고, 임시로 복사한 파티가 잘못 남지 않는지
4. 도둑미러에서는 원래 파티 보유 규칙을 유지하면서 승패 처리가 정확한지
5. 일반 모드, 화이트아웃 면제 전투, 시설·파트너 전투의 기존 예외가 유지되는지

배지 지급 검사는 디버그 단독 배틀만으로 끝내지 말고 실제 체육관 이벤트에서도 확인해 줘. 수정 커밋과 전후 비교 결과를 남기고, 재확인 35는 **수정 반영 후 사용자 실기 대기**로 관리하자.

## 4. 공생 및 야생전 도구 복구 — #10483 / #10577

도구 도난 기록 때문에 공생이 잘못 막히는 부분을 수정하고, 야생전에서 잃은 도구의 기존 복구 동작을 유지한 방향에 동의해.

공생으로 도구를 전달하는 상황은 실제 도난 이력이 있는 경우와 없는 경우를 비교해 줘. 디버그로 도구를 바꾸는 것만으로 실제 도난 기록이 생긴 것으로 간주하지는 말아 줘.

야생전 종료 후 도구 복구도 별도로 확인하고, 정상적으로 소모한 나무열매와 도난·상실한 도구의 처리를 구분해 줘. 이번 수정으로 모든 소모 도구를 되돌려 주는 방식으로 바꾸면 안 돼.

## 7. 방벽 진영 문구·배리어프리 타이머 및 HNSSCREEN

`db62d527`의 진영 문구 수정과 `d4e3b8b6`의 배리어프리 타이머 수정은 요청한 방향과 맞아.

기존 한국어 문장·줄바꿈을 유지하면서 실제로 제거된 진영을 기준으로 출력하고, 출력 뒤 공격자 정보를 복구한 방식은 유지해 줘. 배리어프리가 양쪽 방벽을 제거하면 진영마다 문장을 출력하고, 양쪽에 같은 방벽이 있어도 각 진영을 구분하는 현재 처리로 검사할게.

타이머도 실제 제거된 진영·방벽만 초기화하고 관계없는 효과는 보존해 줘. #10829 선반영과 이번 HnS 배리어프리 후속 수정은 기록을 구분하고, seq 551에서 중복 적용하지 말아 줘.

HNSSCREEN을 계속 실행할 수 있는 한국어 회귀 검사로 정리한 결과도 확인했어.

- 15개 테스트·내부 35개 경우
- 수정 전 4/15 → 진영 수정 후 8/15 → 두 수정 후 15/15
- 한글 회귀 기준 532/622, 기존 607개 결과는 유지

테스트 파일·실행 명령·전후 결과와 기대값을 보존해 줘. 영문 기대값 때문에 HnS에서 판정하지 못한 upstream 테스트 2개는 한국어 회귀 결과와 별도로 기록해 줘.

사용자 실기는 다음 조건을 새 ROM에서 확인하겠어.

- 깨뜨리다·사이코팽·레이징불로 방벽을 제거할 때 실제 진영과 방벽 이름이 맞는지
- 제거한 방벽의 원래 만료 시점에 종료 문장이 다시 나오지 않는지
- 배리어프리로 우리 쪽만·상대 쪽만·양쪽 같은 방벽·양쪽 다른 방벽을 제거할 때 문장이 정확한지
- 정상 만료·안개제거·특성 팝업·공격자 복구와 다음 전투 진행이 유지되는지

## 9. 후속 작업과 검증

이번 추가 작업은 **#10568의 보류했던 `battle_setup.c` 수정 적용, 관련 승패·파티 복구·예외 회귀 검사, 결과 문서와 실기용 ROM 정보 갱신**이야.

미러 패배 처리 변경의 결정 근거와 범위를 포트 결과 문서·재확인 35에 남겨 줘. 아테나 회귀는 #8943 이후 발생한 결과값 덮어쓰기 복구로, 미러 패배는 기존 HnS 동작을 이번 프로젝트에서 변경하는 결정으로 구분하자.

그 외에는 seq 323부터 기존 full-sync 순서대로 이어 가 줘. 한국어 처리·메가 특성·파동의방호·HnS 고유 기능·AI 교체 방지 가드·세이브 호환성 보호 원칙과 기존 Q1·Q2 승인은 유지할게.

사용자가 직접 PASS한 실기 결과는 보존하고, 실제 코드 변경으로 영향을 받은 조건만 새 ROM에서 추가 검사하겠어. mGBA 검사는 내가 직접 진행할게.
