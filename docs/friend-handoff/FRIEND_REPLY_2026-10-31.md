# HnS 후속 요청(2) 확인 및 남은 항목 결정

`followup-2026-10-30b.md`와 `survey-2026-10-30-fairy-skydrop.md`의 보고 확인했어.

README 복원, 너즐록 알 보존·회복, 슬라이드 표 축소, Set Ability 취소 방어, 한글 문구 수정은 보고한 방향으로 유지해 줘. 추가 조사로 확인한 내용에 대해서는 아래처럼 결정할게.

이번에도 **네 작업환경에서 수정·빌드·자동 검사를 진행하고, 내 QA 환경과 메인 한글화 로컬은 건드리지 말아 줘.** mGBA 실기는 내가 별도로 진행할게.

## 1. 반영 완료 항목 유지

다음 반영 상태를 유지해 줘.

- **README:** 기존 HnS 크레딧 예시의 1.15.1 원문을 보존하고, 코드 블록 밖에 한글패치의 1.17.1 통합 기반 설명을 추가한 상태.
- **매지컬리프:** 잎 이동 22프레임·`delay 30`·`target_both=FALSE`.
- **엔진 버전:** 1.17.1·`EXPANSION_TAGGED_RELEASE FALSE`.
- **3b 춤추기:** 현재 반영한 동작 유지. b·b2는 적용하지 않음.
- **23:** `B_MULTI_HALF_TEAMS FALSE` 유지.
- **71:** 빈 트레이너 슬라이드 표를 목록과 공용 빈 줄로 바꾼 구조 유지.
- **72:** Set Ability에서 파티 선택 취소값을 검사하고 종료하는 방어 코드 유지.

71의 ROM 절약은 슬라이드 표 변경만 **371,424 B**, 이번 다른 변경까지 합친 순감소는 **371,280 B**로 구분해서 기록해 줘.

슬라이드 테스트도 **75개 결과가 이전과 같음(PASS 25·영문 문장 FAIL 50)**으로 남겨 줘. 75개 전부 PASS로 표현하지 않으면 돼.

인트로·머그샷·승패 대사와 Set Ability 취소의 실제 화면은 내가 새 ROM에서 확인할게.

## 2. 재확인 70 — 일반 보충과 파트너 배틀 처리 유지

### 70(a) 알 보존·보충 후 회복

`338a5ebd`의 다음 처리를 유지해 줘.

- 보충 포켓몬은 0번 칸에 배치.
- 기존 알은 개체와 순서를 유지하면서 뒤로 이동.
- 파티 제한이 꽉 찼으면 마지막 알을 PC로 이동.
- 보충 뒤 마릿수를 다시 계산해서 보충 포켓몬도 회복.

### 70(b) 파트너 배틀

**기절한 원래 포켓몬이 남아 있으면 보충하지 않고, 그 파티를 회복하는 현재 구현을 유지해 줘.**

삭제 면제인 배틀에서는 원래 포켓몬이 회복되므로 박스에서 새 포켓몬을 꺼낼 필요가 없어. ‘덮어쓰기만 막기’라는 요청에 맞는 처리야. 보충하면서 기존 파티를 밀어 넣는 방식으로 바꿀 필요는 없어.

하드 너즐록의 기존 세이브 삭제 규칙과 미러에서 살아 있는 원래 파티를 보호하는 기존 처리도 유지해 줘.

## 3. 재확인 70 — PC까지 꽉 찬 경우

**알이나 묘지 기록을 지우지 않는 ① 방향을 선택할게.** 묘지 칸을 삭제하는 ②는 적용하지 말아 줘.

다만 현재의 ‘알만 있는 파티로 화이트아웃 후 복귀’를 안전한 최종 처리로 확정하려면 다음을 더 확인해야 해.

- 포켓몬센터 복귀 후 PC를 정상적으로 사용할 수 있는지.
- 전투 가능한 포켓몬이 없을 때 야생·트레이너 배틀에 들어가면 어떻게 되는지.
- 저장하고 다시 불러와도 진행 불능이나 데이터 손상이 없는지.
- 플레이어가 스스로 자리를 확보한 뒤 전투 가능한 포켓몬을 얻을 경로가 있는지.
- 자리를 확보한 뒤 꼬렛 보충이 필요하다면, 언제 다시 검사해야 하는지.

네 환경에서 가능한 코드 대조와 자동 검사를 먼저 해 줘. 실제 화면·필드 진행은 내 실기로 남겨도 돼.

**데이터를 보존하는 것과 플레이를 계속할 수 있는 것은 별개로 기록해 줘.** 진행 불능 가능성이 발견되면 알이나 묘지를 자동 삭제하지 말고, 보존하면서 복구할 수 있는 추가 설계를 먼저 알려 줘.

## 4. 재확인 34 — 노가드 × 프리폴은 현재 HnS 유지

**제외한 #10180 hunk는 넣지 말고 현재 HnS 동작을 유지해 줘.**

이번 설명대로 차이는 반무적 상태를 통과하는지 여부가 아니라, 그 뒤에 노가드의 명중 판정 생략을 적용하는지 여부로 이해했어.

현재 HnS처럼 노가드가 관여하면 프리폴 관련 대상에게도 명중 판정을 생략하는 방향으로 유지하자.

기록에는 다음을 구분해 줘.

- 임시 테스트에서 확인한 현재 HnS와 hunk 적용판의 차이.
- Showdown이 현재 HnS와 같은 쪽이라는 보조 근거.
- 본가의 해당 상황을 직접 확인한 근거는 아직 없다는 점.
- 4번도로 동시 발견 더블은 지형을 제외한 기하상 후보이며 실기 재현은 미확인이라는 점.

‘명중 100 기술은 차이가 없다’는 설명도 **이번에 사용한 보정 없는 실험 조건의 결과**로 한정해 줘. 명중·회피 랭크 등이 달라진 상황까지 같은 것으로 일반화하지는 말아 줘.

새 게임 동작을 바꾸는 수정은 하지 말고, 이번 비교에 사용한 조건과 결과를 가능한 범위에서 문서에 남겨 줘.

## 5. 재확인 37 — 팝업 입장 완료까지 최소 대기하도록 수정

**딜레이 생략 ON에서도 팝업이 제자리에 도착할 때까지 기다린 뒤 HP 변화 등 다음 처리가 진행되도록 수정해 줘.**

이번 요청은 다음 기존 처리와 별개야.

- 36: 팝업이 완전히 사라질 때까지 대기.
- 8m: 특성 팝업 이후 도구 팝업이 겹치지 않도록 대기.
- 37: 팝업이 들어오는 동안 다음 처리가 먼저 진행되지 않도록 대기.

수정 범위는 필요한 입장 대기에 한정해 줘.

- 실제로 들어오는 중인 팝업이 있을 때만 기다림.
- 팝업이 이미 도착했거나 없으면 불필요하게 기다리지 않음.
- 팝업이 사라질 때까지 추가로 기다리는 방식으로 확대하지 않음.
- 딜레이 생략 OFF의 기존 순서는 유지.
- 파티·가방 화면 복귀 후 남은 표시 상태 때문에 멈추지 않음.
- 싱글·더블과 연속 특성·도구 팝업에서 다른 배틀러의 상태를 잘못 기다리지 않음.

공통 `pause`의 모든 대기를 되살리기보다는 팝업 입장 상태에 필요한 최소 조건으로 처리해 줘.

과거 약 2.6%는 10월 9일 계측값으로 남겨 두고, 최신 수정의 실측값처럼 쓰지 말아 줘. 이번 환경에서 재계측하지 못하면 미실행으로 기록하면 돼. 실제 화면 순서와 체감 템포는 내가 QA 환경에서 확인할게.

## 6. 재확인 89(1) — 테스트 기본값을 페어리 ON으로 맞추기

원인이 게임 AI가 아니라 테스트 세이브의 페어리 OFF 설정이라는 설명 이해했어.

**HnS 테스트의 공통 준비에서 `tx_Mode_Fairy_Types = 1`로 설정해서 새 게임 기본값과 맞춰 줘.**

게임의 새 게임 설정이나 AI 계산 코드는 변경하지 말아 줘. 드래곤애로우 테스트의 기대 점수를 임의로 바꿀 필요도 없어.

다음도 함께 확인해 줘.

- 페어리 ON에서는 푸크린의 드래곤 무효를 전제로 한 기존 테스트가 정상 동작하는지.
- 페어리 OFF를 명시한 별도 검사에서는 푸크린이 노말이며, 드래곤애로우가 명중하고 해당 AI 평가도 그 조건에 맞는지.
- 특정 테스트가 페어리 OFF를 요구한다면 공통 기본값에 의존하지 않고 해당 테스트에서 명시적으로 설정하는지.
- 테스트 사이에 설정이 남아서 다른 결과를 만들지 않는지.

정식 반영 후 전체 테스트와 한글 회귀를 다시 실행하고 기준 목록을 갱신해 줘.

임시 조사에서 확인한 **새 PASS 14개·사라진 PASS 0개·새로 실행되는 영문 문장 FAIL 16개**는 조사 결과로 보존하되, 실제 반영 후 결과와 따로 적어 줘.

영문 문장 비교에서 멈춘 테스트는 그 이유로 분류하고, 해당 장면의 모든 동작을 검증 완료한 것처럼 처리하지 말아 줘.

## 7. 재확인 82 — 현재 설정 유지

**별도 `HNS_…` 설정 이름을 추가할 필요는 없어.**

Gen9 필드 날씨 규칙을 지원하는 코드는 유지하면서, HnS에서는 `B_OVERWORLD_WEATHER_OVERRIDE GEN_8`로 해당 제한을 사용하지 않는 현재 방식이면 돼.

이번에 추가한 HnS 설명 주석도 유지해 줘. 설정 이름을 늘리는 추가 변경은 하지 말아 줘.

## 8. 재확인 114 — 가방과 PC가 모두 꽉 찬 경우까지 추가 설계

가방 추가가 실패하면 PC 도구 보관함으로 보내는 ①은 개선 방향으로 이해했어.

하지만 **가방과 PC가 모두 꽉 차면 여전히 도구가 사라지므로, 아직 도구 보존 문제의 해결책으로 확정하지는 않을게.**

다음 조건까지 포함해서 추가 설계를 먼저 알려 줘.

- 가방 실패·PC 여유.
- 가방과 PC 모두 실패.
- 훔친 뒤 포획한 경우의 포획 개체 도구 귀속.
- 훔친 뒤 도주하거나 쓰러뜨린 경우의 지급.
- 저장·불러오기 이후에도 도구가 중복되거나 사라지지 않는지.
- 플레이어에게 처리 결과를 알려야 하는지.

②처럼 플레이어 포켓몬에게 일단 지니게 했다가 기존 복구 처리로 사라지는 방식은 적용하지 말아 줘.

이번 답장에서는 **추가 설계만 요청하는 것**이야. 가방·PC 규칙, 세이브 구조, 포획 개체의 도구 귀속을 임의로 바꾸지는 말아 줘.

## 9. 텔레키네시스·불사르기는 정확한 공식 본문으로 수정

두 문장 모두 **공식 대응 본문으로 변경해 줘.**

### 9-1. 텔레키네시스

`STRINGID_HURLEDINTOTHEAIR`를 다음 형태로 바꿔 줘.

```c
"{B_DEF_NAME_WITH_PREFIX}{B_TXT_EULREUL}\n허공에 띄웠다!"
```

이번에는 `은/는`만 고친 현재 본문을 유지하지 않고, 공식 텔레키네시스 문장에 맞춰 목적격 조사와 본문을 함께 바꾸는 결정이야.

받침과 진영에 따라 다음처럼 나와야 해.

- 마자용을 / 피카츄를 / 마릴을.
- 상대 마자용을 / 상대 피카츄를.
- 다음 줄은 `허공에 띄웠다!`.

기술의 성공·실패 조건이나 효과는 변경하지 말아 줘.

### 9-2. 불사르기

`STRINGID_INCINERATEBURN`을 다음 형태로 바꿔 줘.

```c
"{B_EFF_NAME_WITH_PREFIX}의\n{B_LAST_ITEM}{B_TXT_IGA} 불타 없어졌다!"
```

도구 이름에는 `을/를`이 아니라 `이/가`가 붙어야 해.

앞서 전달한 Champions 1496~1499행은 부식가스 문장이었으므로, 불사르기 근거로 연결한 기록을 정정해 줘. 이번에는 네가 확인한 SV 7709행 등의 불사르기 문장을 기준으로 해 줘.

부식가스용 `STRINGID_PKMNITEMMELTED`와 합치거나 문자열 ID를 서로 바꿀 필요는 없어. 현재 불사르기 버퍼를 그대로 사용해서 보유자·도구 이름이 정확하게 나오도록 해 줘.

효과가 막힌 쥬얼에도 문장이 나오는 문제는 계속 별도 동작 문제로 남기고, 이번 본문 수정으로 도구 효과 판정까지 변경하지 말아 줘.

### 9-3. 나머지 문구

- **불새:** 현재 `(으)로부터` 수정 유지.
- **거다이맥스:** 정확한 공식 공통 문장이 확인되지 않았으므로 영문 유지. 자체 번역하지 않음.
- **클래스명:** 현재 번역 경로에서 문제가 재현되지 않았으므로 공통 문자 처리 코드 수정 없음.
- **멸망의바디:** 적용한 공식 문장과 주석 정정 유지.
- **볼 바꾸기:** 요청한 자체 번역·조사·입력 대기 유지.

텔레키네시스와 불사르기 본문 변경 후에는 공식 줄바꿈, 받침별 조사, 양쪽 진영, 긴 이름·도구 이름의 폭을 다시 확인해 줘. 이번 출력에 맞춰 관련 테스트 기대값과 변경 이유도 갱신해 줘.

이번 보고의 새 PASS 20개에는 이름 변경 4개가 포함되어 있으므로, **이름 변경을 제외한 순증은 16개**로 기록해 줘.

새 ROM을 만들면 기준 커밋·SHA1·사용 용량·포함 변경·빌드 환경을 알려 줘. 실제 팝업 템포, 알·PC 포화 후 필드 진행, 각 문장의 화면 출력 등은 내가 QA 환경에서 확인하겠어.

가로챈 멀리짖기 assert와 기존 실기 대기 항목도 그대로 보존해 줘. 이번 후속 작업을 이유로 메가 특성·기존 한글 텍스트·HnS 고유 기능·세이브 구조까지 범위를 넓히지는 말아 줘.
