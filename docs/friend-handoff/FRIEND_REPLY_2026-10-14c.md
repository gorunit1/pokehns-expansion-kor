# HnS 묶음 20·21 확인 및 웅·미러·너즐록 후속 결정안

묶음 20(seq 323~336), 요청 반영 A1~A3, 묶음 21(seq 337~350) 보고 모두 확인했어.

웅 머그샷과 미러 패배 처리의 요청 반영은 보고한 방향으로 유지해 줘. 재확인 66·67은 아래의 제외 유지·보호 장치 유지안으로 답할게. 아테나 원인 설명 정정도 기록하고, 친구의 빌드·자동 테스트·코드 감사와 내 mGBA 실기는 계속 구분하자.

## 1. 웅 머그샷 — 5e7e97c2

`y2 -= 8`을 제거하고, 웅 머그샷이 읽는 그림의 시작 타일을 `sheetTileStart += 8`로 바꾼 뒤 `SetSpriteSheetFrameTileNum()`을 호출하는 수정은 내가 요청한 방식과 맞아.

스프라이트 전체를 위로 옮기는 대신, 기존 머그샷 영역 안에서 그림의 다른 부분을 보여 주는 방식이야. 기존 표시 영역·배율·슬라이드 위치를 유지하면서 머리 위치와 몸 아래 경계가 함께 맞도록 한 현재 코드를 유지해 줘.

상대 A/B 양쪽에 적용하고, 일반 웅과 OBC 이후 웅이 같은 그림 ID를 사용하는 점도 확인했어. 그림 시트 범위 안의 타일을 읽는다는 검증 근거는 결과 문서에 남겨 줘.

내 로컬의 `267b8ec6 + 머그샷 수정` ROM에서는 제공한 한 장면의 머리·몸 표시를 직접 확인했어. 그 PASS는 그대로 보존하되, 일반/OBC 이벤트 전체와 슬라이드 전체를 모두 확인한 결과로 확대하지는 말아 줘.

새 통합 ROM에서는 아직 확인하지 않은 일반·OBC 이벤트 구분, 슬라이드, 일반 배틀 그림, 다른 트레이너 머그샷을 추가로 확인할게.

## 2. 미러 챌린지 패배 — 4de35b2b / 재확인 35

앞서 승인한 `#10568`의 `battle_setup.c` 수정은 그대로 유지해 줘.

원래 파티를 복구한 뒤 살아 있는 포켓몬이 있다는 이유로 패배 후 스크립트에 복귀하던 경로를, 실제 배틀의 패배 결과에 따라 화이트아웃하도록 바꾸는 것이 이번 결정이야.

이 변경은 **이식 전부터 있던 HnS의 동작을 이번 프로젝트에서 바꾸기로 한 것**으로 기록해 줘. 새 full-sync 회귀나 HnS 개발자가 인정한 버그로 표현하지는 말아 줘.

비상 체육관은 배틀 이후 별도 승패 확인 없이 배지·배지 수·날개쉬기 등의 처리가 이어진다는 분석도 이해했어. 새 ROM에서 다음을 확인할게.

- 배지가 없는 상태에서 일반 미러로 비상에게 패배하면 화이트아웃되는지
- 패배로 배지·날개쉬기·배지 수·`FLAG_DEFEATED_VIOLET_GYM` 등 승리 보상이 생기지 않는지
- 다시 말을 걸면 정상 재도전할 수 있는지
- 승리할 때는 기존 보상과 후속 진행이 정상인지
- 원래 파티와 도구가 의도대로 복구되는지

피라미드·트레이너힐·`B_FLAG_NO_WHITEOUT` 등 기존 예외와, 도둑미러·기권·초기 라이벌·재전·시설 배틀의 기존 정책은 각각 구분해서 보존해 줘.

디버그 파트너 배틀 패배도 이번 콜백 변경의 영향을 받는다는 점은 별도 항목으로 기록해 줘. 일반 진행의 미러 패배와 같은 범주로 묶어서 설명하지는 말아 줘.

## 3. 재확인 67 — 너즐록 보호 장치 유지안

**`da0adeaa`의 보호 장치는 유지하는 방향으로 진행해 줘.**

일반 미러가 끝나 원래 파티가 살아 있는 상태로 복구됐는데, 화이트아웃 보충 과정에서 그 포켓몬을 박스 포켓몬이나 꼬렛으로 덮어쓰는 것은 막아야 한다고 생각해.

파티에 살아 있는 포켓몬이 있는 경우에는 보충을 하지 않고, 알을 제외한 전투 가능한 포켓몬이 하나도 없을 때만 기존 너즐록 보충을 실행하는 현재 조건이 적절해 보여.

이것은 살아 있는 원래 포켓몬의 소실을 막는 조치야. 미러의 복사 파티가 쓰러졌다는 이유로 원래 파티까지 죽은 것으로 처리하는 등 너즐록 규칙을 추가로 바꾸라는 요청은 아니야.

일반 너즐록과 쉬운 너즐록을 구분하고, 다음 조건을 검증해 줘.

- 너즐록 + 일반 미러 패배, 박스에 살아 있는 포켓몬이 있는 경우
- 같은 조건에서 박스에 보충할 포켓몬이 없는 경우
- 원래 파티 6마리의 종·개체·이름·특성·기술·도구·순서·수가 보존되는지
- 보충하지 않아야 하는 상황에서 박스 포켓몬이 이동하거나 사라지지 않는지
- 일반 너즐록 전멸 때는 기존 박스 보충 또는 꼬렛 지급이 그대로 동작하는지
- 너즐록 기권과 미러 재전 패배에서도 살아 있는 파티를 덮어쓰지 않는지
- 알을 살아 있는 전투 가능 포켓몬으로 세지 않는지

화이트아웃에 따른 정상 회복과 부활 위치 이동은 그대로 유지해 줘. 실제 파티·박스 보존 검사는 세이브 정적 비교와 구분해서 기록하고, 내 실기도 원본 세이브의 사본으로 진행할게.

## 4. 재확인 66 — #10645의 GetBattleMoveTarget 부분 제외 유지안

**문제가 재현된 `GetBattleMoveTarget`의 4줄은 계속 제외해 줘.**

upstream과 같게 만드는 과정에서 상대가 손가락흔들기·잠꼬대 등으로 경혈찌르기를 불렀을 때 플레이어 왼쪽 포켓몬의 능력치가 오르는 잘못된 동작까지 넣을 필요는 없어.

경혈찌르기의 다른 수정, 즉 파트너가 이미 기절한 경우와 선택 후 같은 턴에 기절한 경우에 자기 자신을 대상으로 바꾸는 처리는 유지해 줘.

다음 상황은 각각 구분해 확인해 줘.

- 파트너가 이미 기절한 상태에서 직접 경혈찌르기를 선택
- 파트너를 대상으로 선택했지만 실행 전에 같은 턴에 파트너가 기절
- 살아 있는 파트너를 정상적으로 대상으로 선택
- 상대가 손가락흔들기·잠꼬대 등으로 경혈찌르기를 호출하고, 상대 파트너가 살아 있는 경우

마지막 경우에 플레이어 쪽으로 대상이 잘못 넘어가지 않는지 확인해 줘. 손가락흔들기는 실제로 경혈찌르기가 나온 경우만 검사 결과로 인정하자.

이 부분은 HnS에서 유지한 예외와 재현 근거를 포트 문서에 남겨 줘. 뒤의 대상 처리 리팩터에서도 같은 문제가 다시 들어오지 않도록 확인하고, upstream에서 수정되면 그때 비교하자.

## 5. 아테나 멀티 원인 정정과 #10711의 HnS 판정

**재확인 64의 기존 원인 설명은 정정하는 것이 맞아.**

아테나 반쪽 팀 멀티는 `MULTI_BATTLE_CHOOSE_MONS`를 붙이고, 특수 배틀 종류가 `0xFF`로 설정되어 종료 시 `MULTI` 분기를 타지 않는다는 설명을 이해했어.

따라서 “아테나 승리값이 반쪽 팀 판정에 의해 0으로 덮여 화이트아웃됐다”는 이전 설명은 철회해 줘. 실제 실기로 그 현상을 확인한 결과처럼 남기지 말아 줘.

`#10814`의 `32a5fd5a` 한 줄은 풀 팀 멀티의 결과 전달에 필요한 수정으로 유지하고, 순서표 seq 542의 선반영 표시도 유지해 줘. 다만 이것을 아테나 반쪽 팀 승리 버그를 재현·해결한 근거로 사용하지는 말아 줘.

이번 `#10711`은 배틀 시작 전 판정의 별도 문제로 구분하자. 야생전 직후나 이어하기 직후의 지난 배틀 플래그 때문에, 고른 3마리 대신 풀 팀으로 처리될 수 있다는 분석이므로 `AreMultiPartiesFullTeams`의 HnS 판정은 유지해 줘.

HnS 전용 야생전 조건, 모든 조기 반환의 결과값 설정, 시설 분리 처리는 현재 방향으로 보존해 줘. 13/13과 upstream 7/13의 대조 결과는 사용한 조건·명령과 함께 남겨 줘.

내 실기에서는 다음 두 준비 조건을 따로 확인할게.

- B1F에서 야생전을 한 직후 아테나 멀티 시작
- 게임 안에서 저장하고 ROM을 다시 시작해 ‘이어하기’한 직후 아테나 멀티 시작

각각 원래 파티가 6마리인 상태에서 4~6번 칸의 포켓몬을 골라도 선택한 포켓몬이 실제로 나가는지 확인하겠어. 승리·패배 뒤 원래 파티와 도구가 복제되거나 사라지지 않는지도 보겠어.

승리 뒤 퇴각 대사·후속 이벤트, 패배 뒤 화이트아웃 검사도 그대로 유지할게. 코드상 위험 분석, 조사 테스트 결과, 실제 mGBA 결과는 따로 기록하자.

## 6. 묶음 20의 나머지 변경

경혈찌르기 외에도 흉내쟁이가 상대를 쓰러뜨린 기술을 복사하는 수정과, 공생으로 받은 도구가 전체기 반감열매 처리에 다시 사용되지 않도록 한 수정은 보고한 방향으로 유지해 줘.

내 실기 후보에는 흉내쟁이의 실제 복사 기술과 공생으로 전달된 도구의 보존을 넣었어. 관련 배틀 문장과 도구 처리 순서도 함께 확인할게.

수면 클로즈는 현재 HnS에서 꺼져 있고, Z기술·다이맥스는 본 게임 진행에 없는 경로라는 설명도 기록하겠어. 이런 항목은 일반 진행의 필수 실기와 별도 설정이 필요한 검사로 구분하자.

HnS의 상태별 회복 문구와 불복종 처리는 유지해 줘. `HNS9680 3-04`의 상대 HP를 999로 바꾼 것은 수정된 위력에서도 기존 문장 검사를 계속하기 위한 준비 변경으로 기록하고, 문장 기대값은 보존해 줘.

## 7. 묶음 21의 전투 변경

`#10661`의 호출 기술 대상 수정과 `#10682`의 트랩셸 발동 순서 수정은 유지해 줘.

손가락흔들기 등으로 부른 전체기 검사는 기술의 원래 대상에 따라 나눠야 해.

- 스피드스타처럼 상대 둘만 맞는 기술은 사용자 파트너를 맞히지 않아야 함
- 지진·파도타기처럼 원래 아군도 맞는 기술은 정상적으로 아군도 대상이 되어야 함

“호출한 전체기는 모두 파트너를 맞히지 않는다”는 식으로 기록하지 말아 줘.

트랩셸은 물리 전체기를 맞았을 때 해당 공격 직후 발동하는지, 두 포켓몬이 준비한 경우 스피드 순서에 맞는지 확인할게. 같은 행동 순서 함수를 쓰는 추격·당신먼저도 영향이 있는 조건을 자동 회귀 검사로 확인해 줘.

Z기술·지우개굴닌자 등 현재 기본 진행에서 닿지 않는 변경은 그 조건을 명시하고, 이미 적용된 수정·테스트만 추가한 항목·HnS 동등 구현도 포트 순서표에서 구분해 줘.

## 8. #10656 스프라이트 생성 처리와 #10652

`#10656`에서 기존 생성 실패 처리를 활용해 스프라이트 표가 찼을 때 장식을 생략하도록 한 방향은 유지해 줘. HnS 전용 14곳을 함께 처리한 범위와 근거도 기록해 줘.

일반 화면에서 필요한 그림까지 사라지지 않는지, 실패 처리 없는 호출을 같은 방식으로 바꾸지 않았는지 확인해 줘.

실기 후보는 다음처럼 나눠 두었어.

- 타이틀 오프닝과 새 게임 오프닝
- 파도타기 포켓몬, 낙엽·비·모래바람
- 배틀의 마지막 볼 아이콘과 리프블레이드·폴터가이스트·분화·해수스파우팅·싸라기눈 애니메이션
- 공중날기 지도, 도감 분포, PC 박스

스프라이트 표를 실제로 가득 채우는 검사는 일반 화면 검사와 별도 실험으로 관리하자. 내 원본 세이브에서 무리하게 재현할 필요는 없어.

`#10652`의 재 속에 묻힌 트레이너 수정은 Emerald 맵에 해당하는 변경으로 기록해 줘. HnS 일반 진행에서 실제로 접근되는지 확인되지 않은 맵을 필수 실기 대상으로 단정하지는 말아 줘.

## 9. 번역·텅구리 알로라·남아 있는 워프

손가락흔들기 문장의 조사 누락은 기존 텍스트 문제로 번역 대기 목록에 남겨 줘. 지금 친구 쪽에서 임의로 고치거나 다른 기존 문장을 함께 바꾸지는 말아 줘.

나중에 내가 번역할 때 공식 한국어 원문·조사 토큰·줄바꿈·화면 폭을 확인해서 처리할게.

기술 설명과 도감 설명의 아직 미번역인 영문은 앞서 승인한 대로 upstream 갱신을 적용해도 돼. 이미 한글화된 이름·분류·완료한 텍스트는 보존하고, 요청하지 않은 새 한글 번역은 하지 말아 줘.

텅구리 알로라는 커스텀 일반 팔레트와 뒷모습을 유지한 상태로 일반·이로치 화면을 확인할게. 옛 `graphics/pokemon/marowak/alola/front.png` 삭제는 아직 결정하지 않았으니 그대로 두자.

프런티어 동쪽 `(28,7)`의 그림공방동굴 워프도 발견 사항으로 기록만 해 줘. 실제 접근 가능 여부와 용도가 확인되기 전에는 삭제하거나 위치를 바꾸지 말아 줘.

## 10. 자동 테스트 집계와 검증 기록 확인 요청

빌드 성공·새 경고 0·한글 회귀 532/622·세이브 정적 비교 PASS 보고는 친구의 검증 결과로 기록할게. A1~A3의 필드·전환 화면 코드는 코드 감사와 실제 실기가 필요한 영역이라는 설명도 유지해 줘.

다만 전체 테스트 수치는 기준 목록과 보고 사이에 집계 차이가 있어 보여서 확인을 부탁해.

- 보고값: 묶음 20 PASS 2,683 → 묶음 21 PASS 2,684
- 기준 목록의 고유 행 비교: `test-baseline-seq336.txt` PASS 2,679 → `test-baseline-seq350.txt` PASS 2,684

목록에서는 트랩셸 테스트의 옛 이름 1개가 새 이름으로 바뀌었고, 그 외 기존 항목의 상태 변화는 없었어. 하지만 시작 PASS 수가 2,683과 2,679로 달라서 같은 집계 기준인지 확인이 필요해.

전후 실행의 기준 커밋·명령·원본 SUMMARY와, 목록을 만드는 집계 방식을 함께 알려 줘. 중복이나 여러 조건을 묶어 세는 방식 때문에 차이가 난다면 그 이유를 설명해 줘. 숫자를 맞추기 위해 기준 목록을 바꿀 필요는 없어.

새 FAIL의 영문 MESSAGE 불일치는 동작 실패와 구분하되, 그냥 PASS로 처리하지는 말아 줘. 실제 실행 경로가 맞는지 확인한 근거를 남기고, 가능하면 경혈찌르기·호출 전체기·트랩셸·공생 관련 상황을 한국어 기대값으로 계속 실행할 수 있는 회귀 검사로 정리해 줘.

## 11. 실기용 ROM과 검사 기록

이번 최신 실기 기준은 다음 보고값으로 기록할게.

- 코드: `49f2c5e5`
- ROM SHA1: `6377af696d8b505f4e9c28683c21c7e5e0c5dd99`
- ROM 사용량: 32,782,772 B
- 클라우드 GCC 13.2.1 빌드
- 묶음 20·21과 웅·미러·너즐록 보호 장치 포함

이것은 친구가 빌드한 ROM의 정보이고, 내 로컬 웅 검사 ROM과는 별도로 관리하겠어. 다른 환경에서 빌드한 ROM은 그 파일의 해시와 포함 변경을 따로 기록할게.

기존 사용자 PASS는 보존하고, 새 코드로 영향을 받은 조건과 아직 미검사인 항목만 추가로 확인하겠어. 새 통합 ROM의 실기는 아직 완료하지 않았어.

미러·너즐록·아테나 파티 보존, 웅 머그샷의 남은 조건, 경혈찌르기·호출 전체기·트랩셸 외에 텅구리 알로라·오프닝·방벽 진영·배리어프리 등의 기존 대기 항목도 유지할게.

## 12. 후속 작업과 검증

이번 답장의 두 유지안과 아테나 원인 정정은 관련 재확인 항목·결과 문서·인수인계에 반영해 줘. 기존 승인 사항과 임시 반영 상태의 이력도 보존해 줘.

그 외 full-sync는 seq 351부터 기존 순서대로 이어 가 줘. 이후 대상 처리나 멀티 관련 코드를 다시 수정할 때는 이번에 제외·보존한 HnS 동작과 충돌하지 않는지 확인해 줘.

한국어 처리, 메가진화 특성 할당, 파동의방호, HnS 고유 기능, AI 교체 무한 루프 방지 가드, 기존 세이브 호환성은 계속 보존해 줘. 세이브 관련 변경이 나오면 기존 세이브의 영향과 검증 근거를 따로 보고해 줘.
