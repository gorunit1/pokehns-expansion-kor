- 확인할 경로: 빈 칸 학습 / 교체 학습 / 취소·거절 / 연속 학습 / 성공음 뒤 진행.
- 회귀 테스트: 수정 전의 누락을 잡아야 하고, 맞는 곡 요청 1번 + 종료 대기를 확인.
- 과거 upstream 동작과 실제 포팅 전 HnS 동작을 구분할 것. 친구 시험 ROM SHA1 `bddcaf57e3851956dd5bf4a4713075b0435c949c`.
- 자동 테스트와 실제 듣기를 구분할 것(듣기는 친구가 함).

### 포팅 회귀 점검(4~5절)

- 포팅 전 HnS 커밋과 현재 커밋을 SHA로 고정하고, 차이를 **포팅 전부터 있던 것 / 포팅으로 생긴 회귀 / 승인된 의도적 변경 / 불명확**으로 나눈다.
- 호출 경로를 따라가며 확인. 중점: 공통 UI·기술 학습, 음악·효과음, 태스크·콜백, 배틀 공통 처리, HnS 전용 분기.
- 승인된 변경은 되돌리지 않는다. 최소 수정 + 재현 테스트.
- 보고 표 열: 기능 / 포팅 전 기준 / 현재 코드 경로 / 의도적 변경 여부 / 확인한 문제 / 수정 커밋 / 검증 결과 / 남은 실기 조건.
- 본 범위와 보지 않은 범위를 적는다. 전부 보존됐다고 주장하지 않는다.
- 새 ROM 전달 시: 빌드 커밋, ROM SHA1·SHA256, 대응 ELF, 수정 목록, 최소 실기 확인 항목. 내 자동 테스트를 친구 ROM PASS로 적지 않는다.
