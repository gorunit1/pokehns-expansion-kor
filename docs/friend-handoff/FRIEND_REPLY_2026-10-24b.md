# HnS 묶음 32~39 후속 결정 — 회복·방어 애니메이션 / 설명 폭 / AI 테라 설정 / 화학의힘

묶음 32~39(seq 396~468), 코드 `4d9f0306`의 보고 확인했어. 이번에 질문한 항목은 아래 방향으로 진행해 줘.

이번 요청은 서로 독립적인 변경이므로 수정 내용과 검증 결과를 구분해 줘. 기존 한국어 문장·줄바꿈, 메가진화 특성, HnS 고유 기능, 세이브 호환성은 계속 보존해 줘.

## 1. seq 428 — 회복 기술 반짝임은 A안으로 적용

**upstream의 공통 회복 애니메이션 구조를 완성하는 A안으로 진행해 줘.**

빠진 날개쉬기·달의불빛·알낳기·아침햇살 네 기술만 따로 복원하기보다, 공통 회복 처리에서 반짝임이 정상적으로 한 번 재생되도록 맞춰 줘. 회복 연출 때문에 전투가 조금 길어지는 것은 괜찮아.

다음 사항을 확인해 줘.

- 기존에 반짝임이 있던 회복 기술까지 포함해 같은 회복에서 중복 재생되지 않을 것.
- 회복 대상이 사용자와 다른 경로에서도 실제 회복하는 포켓몬에게 연출이 나올 것.
- 광합성·모래모으기 등 개별 기술에 남은 중복 연출은 upstream 변경 의도에 맞게 정리할 것.
- 회복량·발동 조건·기술 효과·한국어 메시지와 줄바꿈은 변경하지 않을 것.
- 배틀 애니메이션 설정에 따른 표시 여부도 기존 규칙을 따를 것.

공통 처리에 `BS_TARGET` 등 대상 지정을 맞출 때는 HnS의 실제 호출 경로를 확인해 줘. 단순히 애니메이션이 나온다는 것뿐 아니라, 올바른 대상에게 한 번 나오는지 검증해 줘.

## 2. seq 441 — 방어 성공 애니메이션은 A안으로 적용

**방어·판별·니들가드 등으로 기술을 막았을 때 방어막과 흔들림 연출을 추가하는 A안으로 진행해 줘.**

실제로 막은 포켓몬에게 연출이 나오고, 이후 기존의 ‘몸을 지켰다!’ 문장이 이어지도록 해 줘. 연출이 조금 길어지는 것은 괜찮아.

다음 사항은 유지해 줘.

- 방어 성공 여부와 연속 사용 성공률
- 니들가드·킹실드 등 각 기술의 접촉 판정과 추가 효과
- 와이드가드 등 진영 단위 방어의 적용 범위
- 기존 한국어 문장과 줄바꿈

싱글·더블에서 연출 대상이 뒤바뀌거나, 연속기·전체기 처리 중 같은 방어 연출이 불필요하게 중복되지 않는지도 확인해 줘. 이미 이식된 방어 관련 동작을 이번 애니메이션 추가 때문에 다시 바꾸지는 말아 줘.

## 3. seq 444 — 설명 글자 폭 맞춤은 A안으로 적용

**창보다 넓은 설명에만 더 좁은 글꼴을 사용하는 기능을 적용해 줘.**

기술 떠올리기 화면의 기술 설명과 요약 화면의 특성 설명 등이 창을 넘을 때, upstream의 폭 계산에 따라 들어가는 글꼴을 선택하도록 해 줘. 현재 글꼴로 들어가는 설명까지 일괄적으로 작게 만들 필요는 없어.

현재 보고한 기술 설명 74개·특성 설명 18개는 **현재 문자열과 설정에서 측정한 대상 수**로 기록해 줘. 앞으로 설명을 한글화하면 대상과 폭이 달라질 수 있으므로, 이 숫자를 고정된 기준으로 사용하지는 말아 줘.

이번에는 다음 범위로 한정해 줘.

- 설명 내용·수동 줄바꿈·창 크기는 그대로 유지
- 이미 한글화된 기술 이름·특성 이름은 그대로 유지
- 설명을 새로 번역하거나 문장을 줄여 쓰지 않음
- upstream이 수정하는 다른 설명 출력 위치도 확인해 누락 없이 적용
- 좁은 글꼴에서도 한글과 제어 코드가 정상 처리되는지 확인

현재 미번역 영문 설명이 들어간다는 검증과, 향후 한글 설명에도 문제가 없다는 검증은 구분해 줘. 실제 가독성·잘림 여부는 내가 새 ROM으로 확인할게.

## 4. 스마트 테라는 이식하고, AI 트레이너 사용 허용 설정을 추가

**upstream의 스마트 테라 대상 선정 변경은 이식하되, AI가 조종하는 트레이너의 테라스탈 사용을 별도로 허용하거나 막는 설정을 추가해 줘. HnS에서는 기본 OFF로 해 줘.**

플레이어가 테라스탈을 사용할 수 있는 조건과 NPC 트레이너의 사용 조건은 별개이므로, 플레이어용 테라스탈오브 소지·충전 조건을 NPC 제한 설정으로 대신 사용하지 말아 줘.

### 4-1. 스마트 테라 이식 범위

upstream처럼 스마트 테라가 지정된 트레이너는 개체에 테라 타입이 명시되지 않았더라도, 엔진이 생성한 유효한 테라 타입을 바탕으로 사용 후보가 될 수 있게 해 줘.

다만 다음 사항은 구분해 줘.

- 스마트 테라 지정은 사용 후보와 AI 판단에 관여하는 조건이야.
- 후보가 된다고 무조건 첫 턴에 테라스탈하거나, 아무 타입으로 자유롭게 바꾸는 것은 아니야.
- 실제 사용은 기존 사용 횟수·배틀 조건·AI 판단 등 관련 제한을 통과해야 해.

테라 관련 후보 선정에 필요한 부분만 맞추고, 다른 AI 판단이나 트레이너 전체의 설정까지 일괄 변경하지는 말아 줘.

### 4-2. 새 설정의 동작

설정 이름은 저장소의 명명 방식에 맞춰 정하고, 완료 보고에 정확한 이름과 위치를 알려 줘. 예를 들어 `B_AI_TERASTALLIZATION` 같은 별도 빌드 설정이면 돼. 이 이름은 제안이므로 기존 설정처럼 기록하지는 말아 줘.

| 설정 | AI/NPC 트레이너 동작 |
|---|---|
| OFF | 개체에 테라 타입이 명시되어 있거나 스마트 테라가 지정되어 있어도 테라스탈을 사용하지 못함 |
| ON | upstream의 후보 선정과 기존 조건·AI 판단에 따라 테라스탈 사용 가능 |

**HnS 빌드의 기본값은 OFF로 해 줘.** 다른 빌드에도 영향을 주는 공통 코드라면, HnS 외 빌드의 기존 기본 동작은 보존해 줘.

이번에는 빌드 설정으로 충분해. 게임 내 옵션 메뉴나 세이브 필드를 새로 추가할 필요는 없어.

### 4-3. 상대와 NPC 파트너 모두 적용

설정은 상대 트레이너뿐 아니라 **목호 같은 AI 파트너에게도 적용**해 줘.

단순히 ‘플레이어 반대편이면 제한’으로 구현하면 플레이어 쪽의 NPC 파트너가 빠질 수 있으니, 실제로 AI가 조종하는 트레이너인지 구분해 줘. 반대로 플레이어 본인이나 통신 상대가 직접 조작하는 포켓몬까지 막으면 안 돼.

가능하면 공통 사용 가능 판정에서 제한하고, OFF일 때는 AI 선택 단계와 실제 발동 단계 모두에서 테라스탈이 발생하지 않도록 해 줘. 개체의 테라 타입만 지워서 제한을 대신하는 방식은 피하고 싶어.

플레이어의 테라스탈오브·충전·배틀별 허용 조건은 그대로 유지하고, 메가진화·Z기술·다이맥스의 사용 조건도 이번 설정으로 바꾸지 말아 줘.

### 4-4. 레드의 기존 테라 지정 해제 요청 유지

앞서 요청한 **레드의 이상해꽃과 팔데아 켄타로스의 테라 지정 해제도 그대로 진행**해 줘. 새 설정 추가를 이유로 이전 요청을 취소하는 것은 아니야.

다만 새 설정이 실제로 작동하는지 확인할 때는, 별도 테스트에서 테라 타입이 명시된 상대도 준비해 줘. 실제 데이터에서 지정이 사라졌기 때문에 테라를 쓰지 않는 것과, 설정 OFF가 사용을 막는 것은 구분해서 검증해야 해.

### 4-5. 검증

다음 조건을 구분해 확인해 줘.

- OFF: 명시적 테라 타입이 있는 상대도 사용 불가
- OFF: 타입이 명시되지 않은 스마트 테라 상대도 사용 불가
- OFF: 플레이어 쪽 NPC 파트너도 사용 불가
- ON: 명시 지정 개체와 스마트 테라 후보가 기존 조건에 따라 사용 가능
- 플레이어의 기존 사용 가능·불가 조건은 전후 동일
- 다른 배틀 기믹과 세이브 구조는 변경 없음

기본 OFF 빌드만 확인하면 스마트 테라 이식 자체의 문제가 가려질 수 있으니, ON 검증도 별도로 해 줘. 테스트 전용 우회 때문에 새 제한이 무시되는 경우가 없는지도 확인해 줘.

## 5. 특성명 ‘과학의힘’을 ‘화학의힘’으로 수정

**`ABILITY_POWER_OF_ALCHEMY`의 한국어 이름을 ‘과학의힘’에서 ‘화학의힘’으로 수정해 줘.**

현재 `src/data/abilities.h`의 해당 특성 이름에 들어간 오역을 고치는 요청이야.

이번 변경은 특성 이름에 한정해 줘.

- 특성 번호와 `ABILITY_POWER_OF_ALCHEMY` 식별자 유지
- 특성 효과·발동 조건·포켓몬별 할당 유지
- 영문 설명은 이번 요청으로 새로 번역하지 않음
- 다른 특성이나 NPC 대사의 ‘과학’ 표현을 일괄 치환하지 않음

동일한 특성을 가리키는 별도 이름표나 테스트 기대값에 같은 오역이 중복되어 있다면 필요한 부분만 함께 맞추고, 변경 위치를 알려 줘.

요약 화면과 특성 팝업 등에서 ‘화학의힘’이 표시되는지 확인하고, 이름 수정 때문에 기존 특성 동작이 달라지지 않도록 해 줘.

이번 변경은 가능하면 다음 단위로 커밋과 결과를 구분해 줘.

추가로, 앞선 실기 후보의 ‘쾌청·비에서 솔라빔이 바로 나감’은 기대 동작을 정정해 줘. **솔라빔의 날씨에 의한 충전 생략은 햇살, 일렉트로빔은 비**를 기준으로 확인해야 해. 비라는 이유만으로 솔라빔이 즉시 발사되는 것으로 검사하지 말아 줘.

완료 시 다음 내용을 알려 줘.
