## 1. 재확인 79 — 알기술 전수 최종 결정

기존 HnS 방식과 upstream 1.17.1 방식을 비교한 결과, 다음 조합으로 진행하기로 결정했어.

**Gen9에서는 같은 종끼리도 흉내허브를 요구하고, 전수 검사는 포켓몬을 맡길 때마다 진행하되, 배울 기술은 가르치는 포켓몬의 기술칸 순서대로 선택해 줘.**

upstream 함수를 통째로 덮어쓰지 말고, 이 결정에 필요한 부분만 HnS에 맞춰 반영해 줘.

### 1-1. 세대별 알기술 전수 조건

**Gen8**

기존 HnS 동작을 유지해 줘.

- 같은 종끼리는 흉내허브 없이 알기술 전수 가능
- 배우는 포켓몬에게 빈 기술칸이 있어야 함
- 가르치는 포켓몬이 해당 기술을 실제로 알고 있어야 함
- 배우는 포켓몬의 유효한 알기술만 전수 가능
- 다른 종끼리 흉내허브를 이용하는 Gen9 기능은 추가하지 않음

**Gen9 이상**

같은 종인지 다른 종인지와 관계없이, **배우는 포켓몬이 흉내허브를 지니고 있어야만 알기술을 전수받도록 변경**해 줘.

다음 조건도 지켜 줘.

- 배우는 쪽에 빈 기술칸이 있어야 함
- 가르치는 쪽이 해당 기술을 실제로 알고 있어야 함
- 해당 기술이 배우는 쪽의 유효한 알기술이어야 함
- 흉내허브는 반드시 배우는 쪽이 지녀야 함
- 가르치는 쪽만 흉내허브를 지녔다면 전수되지 않음
- 전수 과정에서 흉내허브는 소비되지 않음
- 성별이나 알그룹이 다르다는 이유만으로 전수를 막지 않음

현재 HnS의 Gen9 설정에서 같은 종끼리 도구 없이 전수되는 예외는 제거해 줘.

전수 기능이 꺼지는 기존 세대 및 설정의 동작은 유지해 줘.

### 1-2. 알기술 전수 검사 시점 — HnS 방식 유지

**포켓몬을 키우미집에 맡길 때마다 전수 조건을 검사하는 현재 HnS 방식을 유지해 줘.**

다만 양쪽에 유효한 포켓몬이 모두 있는 경우에만 전수가 이루어져야 해.

다음 상황에서도 정상 동작하도록 확인해 줘.

- 첫 번째 포켓몬을 맡긴 뒤 두 번째 포켓몬을 맡기는 경우
- 한 마리를 찾아갔다 다시 맡기는 경우
- 포켓몬을 맡기는 순서를 바꾸는 경우
- 첫 번째와 두 번째 자리 중 어느 쪽이든 전수받는 포켓몬이 될 수 있는 경우
- 한 마리만 맡겨져 있거나 다른 자리가 비어 있는 경우에는 잘못된 데이터 접근이나 전수가 발생하지 않을 것

검사 시점을 upstream의 '두 번째 칸을 채울 때만 검사'하는 방식으로 바꿀 필요는 없어.

추가로, 이전에 보고한 'upstream은 첫 번째 포켓몬을 찾아갔다 다시 맡기면 전수가 안 된다'는 설명은 재확인해 줘.

Codex가 확인한 upstream 1.17.1에서는 포켓몬을 찾아갈 때 남은 포켓몬을 첫 번째 칸으로 이동시키는 처리가 있었어.

따라서 실제 재현 근거가 없다면 해당 설명을 정정해 줘.

### 1-3. 전수할 기술 선택 순서 — upstream 방식 채택

**전수 가능한 기술이 여러 개라면 가르치는 포켓몬의 첫 번째 기술칸부터 순서대로 검사하도록 변경해 줘.**

현재 HnS처럼 내부 알기술 목록의 등록 순서에 따라 기술을 선택하면 안 돼.

예를 들어 가르치는 포켓몬이 전수 가능한 기술 ㉡과 ㉠을 그 순서대로 배우고 있고, 전수받는 포켓몬의 빈 기술칸이 하나뿐이라면 ㉡을 먼저 배워야 해.

다음 조건도 지켜 줘.

- 빈 기술칸이 여러 개라면 가르치는 포켓몬의 기술칸 순서대로 채움
- 전수할 수 없는 기술은 건너뛰고 다음 기술을 검사
- 이미 알고 있는 기술은 중복으로 추가하지 않음
- 같은 기술이 중복으로 발견되더라도 빈 기술칸을 중복 소비하지 않음
- 빈 기술칸을 모두 채우면 종료
- 기존 기술을 삭제하거나 덮어쓰지 않음
- 가르치는 포켓몬의 기술과 지닌 도구는 변경하지 않음

이 방식은 사용자가 가르치고 싶은 기술을 앞에 배치할 수 있다는 편의성과 upstream과의 일치를 고려한 결정이야.

다만 **공식 SV 게임에서 복수 기술의 전수 순서까지 실기로 확인한 것은 아니므로, 해당 사항을 공식 게임과 완전히 동일하다고 기록하지 말아 줘.**

### 1-4. 기존 HnS 처리 보존

이번 변경은 기존 포켓몬 사이의 알기술 전수 조건, 검사 시점, 기술 선택 순서에 한정해 줘.

다음 사항은 변경하지 말아 줘.

- 알을 생성해 자식에게 기술을 물려주는 처리
- 폼 및 볼 상속
- 부화 및 색이 다른 포켓몬 판정
- 너즐록의 알 보호·보충 규칙
- HnS의 향로 베이비와 비베이비 알기술 목록 구분 처리

특히 향로 베이비와 비베이비의 알기술 목록을 따로 확인하는 기존 처리는 유지해 줘.

기술 선택 순서만 가르치는 포켓몬의 기술칸 순서로 변경하고, 전수 가능한 기술인지는 현재 HnS의 목록을 기준으로 검사하면 돼.

알기술 목록 자체와 공식 게임 사이의 차이가 추가로 발견되면 별도로 보고해 줘.

또한 SV는 피크닉에서 알기술을 전수하지만 HnS는 키우미집을 사용하므로, 이번 변경은 **'SV식 도구 조건을 HnS 키우미집에 적용한 것'**으로 기록해 줘.

### 1-5. 알기술 전수 회귀 검증

검증에는 반드시 실제 HnS 학습 데이터에서 성립하는 포켓몬·기술 조합을 사용해 줘.

1. **Gen8:** 같은 종·흉내허브 없음은 전수되고, 다른 종은 흉내허브가 있어도 전수되지 않는지 확인.
2. **Gen9:** 같은 종과 다른 종 모두 배우는 쪽에 흉내허브가 있을 때만 전수되는지 확인. 도구가 없거나 가르치는 쪽만 도구를 지닌 경우도 확인.
3. **빈칸·중복:** 기술칸이 가득 찬 경우 기존 기술 보존, 이미 알고 있는 기술 및 전수 불가 기술 건너뛰기 확인.
4. **전수 순서:** 빈칸 하나에 전수 가능한 기술 두 개를 준비하고, 가르치는 포켓몬의 기술칸 순서를 뒤집으면 배우는 기술도 달라지는지 확인. 빈칸 여러 개도 확인.
5. **맡기기·찾아가기:** 첫 번째와 두 번째 자리 양쪽으로 전수되는지, 맡기는 순서 변경 및 찾아갔다 다시 맡기는 경우에도 정상인지 확인. 한 마리만 맡긴 경우도 확인.
6. **데이터 보존:** 흉내허브가 소비되지 않고, 기존 기술·도구·개체 데이터가 의도한 전수 외에는 변경되지 않는지 확인.

앞서 알기술 테스트 6개가 HnS 학습 데이터 차이로 ASSUME에서 멈췄다고 했으므로, 그 결과를 검증 완료의 근거로 사용하지 말아 줘.

실제 HnS에서 실행 가능한 포켓몬·기술 조합으로 회귀 검사를 준비하고, 검사를 실행했다면 그 결과를 알려 줘.

## 2. HGSS 트레이너 발견 BGM 대응 확인

HnS에는 HGSS의 트레이너 발견 BGM 9종과 라이벌 등장 BGM이 이미 수록되어 있어.

이번에는 이 곡들이 HnS의 각 트레이너 유형에 적절하게 지정되어 있는지 확인해 줘.

### 2-1. 확인 대상 BGM

| 음악 ID | 유형 |
|---|---|
| `MUS_HG_ENCOUNTER_GIRL_1` | 성도 여성 트레이너 |
| `MUS_HG_ENCOUNTER_BOY_1` | 성도 남성 트레이너 |
| `MUS_HG_ENCOUNTER_SUSPICIOUS_1` | 성도 수상한 인물 |
| `MUS_HG_ENCOUNTER_SAGE` | 수행자 |
| `MUS_HG_ENCOUNTER_KIMONO_GIRL` | 기모노 소녀 |
| `MUS_HG_ENCOUNTER_ROCKET` | 로켓단 |
| `MUS_HG_ENCOUNTER_GIRL_2` | 관동 여성 트레이너 |
| `MUS_HG_ENCOUNTER_BOY_2` | 관동 남성 트레이너 |
| `MUS_HG_ENCOUNTER_SUSPICIOUS_2` | 관동 수상한 인물 |
| `MUS_HG_ENCOUNTER_RIVAL` | 라이벌 |

위의 성도·관동 구분은 음악의 원작 분류를 나타낸 것이므로, 실제 적용 대상은 HGSS의 트레이너 클래스별 대응 관계를 참고해 확인해 줘.

**HnS와 HGSS에 등장하는 모든 트레이너를 1:1로 일치시킬 필요는 없어.**

확인할 것은 HnS의 각 트레이너가 자신의 유형에 적절한 HGSS 발견 BGM을 사용하고 있는지야.

HnS에만 등장하는 트레이너는 성격과 유형이 가장 가까운 기존 발견 BGM을 사용하도록 판단해 줘.

다만 다음 원칙은 지켜 줘.

- 이미 올바르게 지정된 음악은 변경하지 않음
- 잘못 지정되었거나 누락된 경우에만 최소 수정
- HGSS의 트레이너 유형별 발견 음악 대응을 우선 참고
- HnS 고유 트레이너는 합리적인 대응 관계를 적용하고 판단 근거를 보고
- 관장·사천왕·챔피언·라이벌 등의 특수 이벤트 음악은 보존
- 기존 배틀 BGM과 승리 BGM은 이번 작업에서 변경하지 않음

이번 작업의 목적은 모든 트레이너를 동일하게 만드는 것이 아니라, **트레이너 발견 음악의 유형별 대응 관계를 점검하는 것**이야.

## 3. 목호전 이후 호두·오박사 등장 BGM 추가

HGSS 원작에서는 챔피언 목호에게 승리한 뒤 호두와 오박사가 등장할 때 여성 트레이너 발견 BGM이 재생돼.

원작 근거는 다음 스크립트야.

`pret/pokeheartgold/files/fielddata/script/scr_seq/scr_seq_0824_T10R0601.s`

원작에서는 해당 장면에 다음 명령을 사용해.

```asm
StopBGM 0
PlayBGM SEQ_GS_EYE_J_SHOUJO
```

이 곡은 HnS의 `MUS_HG_ENCOUNTER_GIRL_1`에 해당해.

현재 HnS에는 호두와 오박사의 등장 이벤트가 있지만 해당 장면에서 BGM이 전환되지 않으므로, HGSS 원작과 동일하게 수정해 줘.

**수정 파일**

`data/maps/PokemonLeague_ChampionsRoom_hns/scripts.inc`

**수정 대상 이벤트**

- `PokemonLeague_WillsRoom_EventScript_LanceOnDefeatJohto`
- `PokemonLeague_WillsRoom_EventScript_LanceOnDefeatKanto`

두 이벤트 모두 목호전 승리 후 호두와 오박사가 등장하는 장면에서 `MUS_HG_ENCOUNTER_GIRL_1`을 재생하도록 해 줘.

재생 시작 시점은 HGSS 원작처럼 문이 열리고 호두와 오박사가 등장하기 직전으로 맞춰 줘.

이때 기존 BGM을 정리하고 발견 음악을 재생하는 과정도 HnS 엔진에 맞게 처리해 줘.

또한 전당등록 방으로 넘어갈 때 발견 음악이 잘못 남거나 다시 재생되지 않도록 해 줘.

다음 사항은 유지해 줘.

- 목호전 배틀 BGM
- 목호전 승리 후 기존 대사
- 호두와 오박사의 등장 및 이동 연출
- 성도·관동 챔피언 등극에 따른 이벤트 분기
- 전당등록 화면의 `MUS_HG_HALL_OF_FAME`

전당등록 방의 기본 BGM과 실제 전당등록 화면의 BGM은 별개이므로, 이전에 결정한 HGSS 원작화 방침과 충돌하지 않도록 해 줘.

**HGSS 트레이너 발견 BGM**

- 확인한 트레이너 유형별 BGM 대응표
- 잘못 지정되거나 누락된 항목
- 실제 수정한 트레이너 및 파일 목록
- 목호전 이후 호두 등장 BGM의 적용 위치
- 전당등록 이동 시 음악 전환의 정적 확인 결과
- 기존 이벤트 및 배틀 음악에 대한 영향 여부

빌드·자동 테스트·세이브 정적 비교·사용자 mGBA 실기는 서로 다른 검증 단계이므로, 수행 여부와 결과를 명확하게 구분해 줘. 실행하지 않은 검사는 PASS로 기록하지 말아 줘.

실기용 ROM을 생성한 경우에는 기준 커밋, SHA1, 빌드 환경도 함께 알려 줘.

**mGBA 실기 검사는 내가 직접 진행할게.** 메인 로컬 저장소에는 Git 동기화나 강제 변경을 하지 말고, 친구가 작업 중인 기존 브랜치에서 필요한 부분만 수정해 줘.
