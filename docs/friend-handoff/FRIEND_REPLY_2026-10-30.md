# 친구 답 2026-10-30: 매지컬리프 연출(재확인 108) + 엔진 버전 표시

사용자가 2026-10-30 전달한 원문이다(같은 날 받은 [`FRIEND_REQUEST_2026-10-30.md`](FRIEND_REQUEST_2026-10-30.md) 버그 수정 8건 요청 다음). 결과는 [`results/1.17.0-port/full-sync-completion-1.17.1.md`](results/1.17.0-port/full-sync-completion-1.17.1.md) 6절.

---

1. HnS 최종 결정 — 매지컬리프 연출 유지 및 엔진 버전 갱신
묶음83~87과 seq1~556의 이식 완료 보고 확인했어. 매지컬리프와 엔진 버전 표시는 다음과 같이 정리해 줘.
   1. 매지컬리프 — upstream과 같은 22프레임 적용
재확인108은 upstream과 동일하게 잎 이동 시간을 22프레임으로 변경하는 것으로 결정할게.

현재 HnS에서 별도로 유지한 `duration=32` 두 줄 대신, upstream #10401의 `create_razor_leaf_cutters target_both=FALSE`를 사용하는 형태로 맞춰 줘.
   * 잎 두 개의 이동 시간은 `duration=22` 적용
   * 타격 연출 전 `delay 30`은 upstream과 동일하게 유지
   * 선택한 상대를 향하는 `target_both=FALSE` 유지
   * 이미 적용한 나뭇잎·시드플레어의 대상 수정은 그대로 유지

잎이 기존보다 10프레임 빨리 도착하고, 타격 연출보다 약 8프레임 먼저 도착한다는 점도 이해했어. 타격 시점까지 함께 앞당기는 추가 수정은 하지 말아 줘.

이번 결정은 upstream의 연출과 코드 구조에 맞추는 선택으로 기록해 줘. 본가와 동일하다고 검증된 변경이라는 뜻은 아니야.

변경 커밋과 upstream 대조 결과를 알려 줘. 실제 잎 이동·타격 타이밍은 내가 새 ROM에서 확인할게.
   2. 엔진 버전 표시 — 1.17.1로 갱신
`include/constants/expansion.h`의 엔진 버전 숫자를 1.17.1로 갱신해 줘.

```
#define EXPANSION_VERSION_MAJOR 1
#define EXPANSION_VERSION_MINOR 17
#define EXPANSION_VERSION_PATCH 1
```

이 숫자는 디버그 메뉴의 `Expansion version`과 ROM 내부 `RHHEXP` 확장 헤더에 들어가는 기반 엔진 정보로 이해했어. seq1~556의 이식이 끝났으므로 실제 기반에 맞춰 갱신하는 데 동의해.

이번 요청은 엔진 버전 숫자의 갱신이야. HnS 게임 이름·타이틀이나 한글패치 자체의 배포 버전은 변경하지 않아도 돼. `EXPANSION_TAGGED_RELEASE`도 이번에는 현재 `FALSE`를 유지해 줘.

또한 엔진 버전이 1.17.1로 표시되는 것과 최종 검증·통합·배포 완료는 구분해서 기록해 줘. `RECHECK_BEFORE_COMPLETION.md` 최종 재확인과 남은 사용자 실기는 계속 진행할게.
   3. 반영 확인 및 완료 보고
두 항목의 결과를 구분해서 알려 줘.
   1. 매지컬리프가 upstream과 같은 22프레임으로 변경됐는지, 타격 대기 30프레임과 단일 대상 설정을 유지했는지.
   2. 엔진 버전 숫자를 바꾼 파일과 커밋.
   3. 다음 검증 빌드에서 디버그 버전 문자열과 `RHHEXP` 헤더의 숫자가 모두 1.17.1을 가리키는지.
   4. 실기용 ROM을 생성했다면 기준 커밋·SHA1·사용 용량·빌드 환경.

이 두 항목 때문에 전체 자동 검사를 별도로 다시 돌릴 필요는 없어. 필요한 빌드·정적 확인 결과를 보고하고, 실행하지 않은 검사와 사용자 mGBA 실기는 미실행으로 구분해 줘.
