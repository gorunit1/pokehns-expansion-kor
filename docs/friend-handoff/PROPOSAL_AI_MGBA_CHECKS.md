# 제안: AI가 mGBA MCP로 실기 확인 일부를 대신하기

> **상태: 검토 중이며 확정이 아니다.**
> - 아직 아무것도 설치하지 않았다.
> - 실기 확인 절차는 지금과 똑같다. 친구가 mGBA로 확인한다.
> - 도입 여부, 범위, 운영 규칙은 **친구(저장소 소유자)와 합의한 뒤** 정한다. 이 문서의 규칙은 합의 전까지 적용하지 않는다.
>
> 작성: 2026-09-30, 사용자 요청으로 조사한 결과를 공유한다.

## 1. 배경

- full-sync 이식에서 가장 느린 단계가 실기 확인이다. 확인 목록이 구간마다 쌓이고, 지금은 친구가 전부 손으로 확인한다.
- Claude가 MCP 서버를 통해 mGBA를 직접 조작하면, 목록 중 **기계적으로 확인할 수 있는 항목**을 먼저 걸러낼 수 있다. 예: 메모리 값, 특정 화면의 글자.
- 그러면 친구는 체감과 최종 판단에 집중할 수 있다.

## 2. 대신할 수 있는 것과 없는 것

**AI가 잘하는 것**
- **메모리 값 확인**
  - 세이브 구조체, `berryTrees`, 파티·박스, 플래그를 이식 전후로 정확히 비교한다.
  - 세이브 호환 확인(예: seq 107 #7305)은 사람이 보는 것보다 정확하다.
- **특정 화면 스크린샷**
  - 한글 글자 깨짐, 조사, 줄바꿈, 창 넘침, UI 픽셀 침범을 본다(예: Safari 흰 줄).
- **같은 조건 재현 비교**
  - 같은 세이브와 같은 입력으로 이식 전후 ROM의 화면을 비교해 작은 차이를 찾는다.

**AI가 대신할 수 없는 것 (친구 확인 유지)**
- 애니메이션의 자연스러움, 타이밍, 효과음, 체감 난이도
- 긴 플레이
  - 버튼을 누를 때마다 스크린샷으로 확인하는 방식이라 느리고, 조금만 어긋나도 엉뚱한 곳으로 간다.
  - 그래서 **확인할 장면 직전의 세이브를 사람이 만들어 주는 방식**이 전제다.
- 최종 판단. AI 확인 결과는 참고용이고 친구 확인을 대신하지 않는다.

## 4. mgba-live-mcp 코드 검토 요약

검토 기준 커밋은 `bacaf68`(2026-09-19)이다. 설치나 실행은 하지 않고 코드만 읽었다.

- **실행하는 명령:** `mgba-qt`(또는 `mgba`)만 실행한다. 인자는 `--script 브리지.lua -l 로그레벨 [-t 세이브스테이트] [-C 설정] ROM`이다. 셸을 거치지 않는다.
- **네트워크:** 실행 중에는 쓰지 않는다. 테스트용 ROM 다운로드 코드는 서버에서 쓰지 않는다. 포트를 열지 않고 명령·응답 파일로 통신한다.
- **파일:** `~/.mgba-live-mcp/runtime/`에 세션 로그, 통신 파일, 스크린샷을 둔다. mGBA 자체는 `.sav`를 ROM 옆에 만든다.
- **의존성:** `mcp`, `pydantic`, `jsonschema`, `Pillow`
- **주의 1:** `mgba_live_run_lua` 도구는 설명에 "제한 없는 Lua. 파일과 프로세스를 바꿀 수 있음"이라고 적혀 있다. 이 도구를 쓸 때는 매번 사람의 승인을 받는다.
- **주의 2:** PyPI의 `mgba-live-mcp` 0.5.0(2026-04)과 GitHub 코드(2026-09)는 같은 버전 번호지만 내용이 다르다. PyPI 메타데이터에는 저장소 링크도 없다. 그래서 설치는 **검토한 GitHub 커밋에 고정**한다.
  ```bash
  claude mcp add --scope user mgba -- uvx --from git+https://github.com/penandlim/mgba-live-mcp@bacaf68 mgba-live-mcp
  ```
- **필요 조건:** Qt와 Lua 스크립팅을 켜고 빌드한 mGBA(0.10 이상)가 필요하다. WSL에서는 WSLg 또는 xvfb가 필요하다.

## 5. 도입한다면 쓸 운영 규칙 (초안, 합의 전 미적용)

1. **도구 위치:** MCP는 사용자 범위(`--scope user`)로 등록한다. 저장소에는 설정 파일을 넣지 않는다. 설치할 기기는 한 대로 정한다(후보: 데스크탑).
2. **ROM:** 확인할 ROM은 저장소 밖(예: `~/hns-mgba-test/`)에 복사해서 띄운다. `.sav`와 스테이트도 그 폴더에 둔다.
3. **세이브:** 세이브스테이트는 **같은 ROM 안에서만** 쓴다. 이식 전후처럼 ROM이 다르면 게임 내 저장(`.sav`)으로 비교한다(기존 규칙과 같다).
4. **기록:** AI가 확인한 항목은 결과 문서에 **"AI 실기 확인(mGBA MCP)"**으로 따로 표기한다. 친구 확인과 섞지 않는다. 스크린샷과 읽은 값은 근거로 남긴다.
5. **최종 확인:** 친구 확인 목록은 줄이지 않는다. AI 확인에서 문제가 나온 항목은 우선순위를 올리고, 통과한 항목은 "AI 사전 확인 통과"로 표시한다.
6. **Lua 실행:** 메모리 쓰기나 세이브 조작이 필요할 때만 쓰고, 그때마다 승인을 받는다.

## 6. 첫 시험 후보

**seq 107 #7305 세이브 호환:** 이식 전 세이브의 `berryTrees` 값이 이식 후 ROM에서도 같은 열매로 읽히는지 본다.
- 노트북 세션이 만든 파일 기반 확인 도구 [`results/1.17.0-port/berry-7305/README.md`](results/1.17.0-port/berry-7305/README.md)가 이미 있다.
- MCP로 실제 ROM을 띄워 같은 값을 메모리에서 읽고 두 결과를 대조하면, 도구가 믿을 만한지와 MCP 확인이 쓸 만한지를 함께 볼 수 있다.
