## 1. 판정 기준과 방법

- 새 지시서의 4개 판정만 사용했다. "선행 필요", "충돌", "나중에"는 쓰지 않는다.
  - `이식`: 이식할 엔진 변경. 선행 리팩터가 있으면 `deps`에 적고, 충돌은 적응 방법을 `approach`에 적는다.
  - `동등`: 현재 HnS에 같은 효과가 이미 있다. 파일:라인 근거를 붙였다.
  - `무관`: 문서·CI·마이그레이션 스크립트 전용이라 빌드 결과에 영향이 없다.
  - `외부결정`: 이식하면 HnS 사용자 지정 동작이 필연적으로 바뀐다.
- 어제 "무관"이던 항목은 다시 판정했다. upcoming 리팩터가 만든 회귀를 고치는 PR, FRLG 전용 코드, config로 꺼진 기능의 코드는 모두 엔진 코드이므로 `이식`이다.
- 테스트 전용 PR도 `이식`(`kind=test`)으로 분류했다.
- 방법:
  - 현재 브랜치(`e95679c545`) 스냅샷에서 PR마다 `git apply --check` / `-R --check`를 다시 돌렸다.
  - 6개 영역으로 나눠 HnS 코드와 upstream diff를 직접 대조했다.
  - 의존성은 upstream `git blame`과 심볼 추적으로 뽑았다.
  - 전체 순서는 의존 관계를 따르되, 같은 조건이면 upstream 커밋 순서를 먼저 두는 위상 정렬로 정했다. 순환은 없었다.

## 7. 자동 테스트

- **원인:** `make check`는 `test/test_runner.c` 2행에서 `fake_rtc.h`를 `global.h`보다 먼저 include해서 멈춘다. HnS 커밋 `16ca5376eb`에서 생긴 문제다.
- **수정:** include 순서를 바꾸는 1줄이다. upstream #9892 첫 hunk와 같고, 게임 ROM에는 영향이 없다.
- **실행:** `make check BUILD=hns`로 해야 한다.
- **예상 결과:** 약 2,131개 테스트(배틀 테스트의 약 50%)가 실패할 것으로 추정한다(정적 스캔). HnS 배틀 문자열과 종명이 한글이라 영문 `MESSAGE` 기대값과 맞지 않기 때문이다. 메시지와 무관한 동작 테스트는 이식 검증에 쓸 수 있다.
- **추가 위험:** TEST 빌드는 `-ffunction-sections`를 끈 상태라 ROM 한도를 넘을 수 있다(추정). 실제로 빌드해 확인한다.
