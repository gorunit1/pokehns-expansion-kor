# 메가진화 특성 — 인수인계 문서와 현재 코드 대조 (2026-10-12)

친구 요청 [`FRIEND_REPLY_2026-10-12.md`](../../FRIEND_REPLY_2026-10-12.md) 3절. 기존 인수인계 문서에 남은 메가진화 특성 할당 기록과 현재 코드(`src/data/pokemon/species_info/gen_*_families.h`의 `*_MEGA*` `.abilities`)를 대조했다. **코드는 고치지 않았다.**

## 1. 결론

- **어긋나는 곳 없음.** 메가 엔트리 99개 모두 현재 코드(HEAD `ffd9464a`)가 친구의 메가 특성 작업이 처음 들어간 커밋 `1821fd6749`(2026-09-26 "Upload current HNS worktree")와 같다. full-sync 포트(seq 1~285)와 그 뒤 작업이 메가 특성을 바꾼 곳은 없다.
- 문서에 종별 값이 적힌 기록(아래 2절 B~G)은 모두 현재 코드와 같다.
- **대여르(`FALINKS_MEGA`) = `{ ABILITY_DEFIANT, ABILITY_DEFIANT, ABILITY_DEFIANT }` = 오기×3**(`gen_8_families.h:5330`, 이름 `src/data/abilities.h` `[ABILITY_DEFIANT]` = `오기`). 상세 결과 문서·재확인 57의 "Defiant×3"이 맞다. 묶음 15 디스코드 요약의 "불굴의마음×3"(= `ABILITY_STEADFAST`)은 요약을 쓸 때의 오기재이고, 설정은 바뀐 적이 없다(저장소 문서에는 "불굴의마음×3"이 없다).
- **파동의방호:** `ABILITY_AURA_GUARD = 319`, 이름 `파동의방호`, 설명 `접촉 기술로 입는 데미지가 반감된다.`, 효과 `src/battle_util.c` `GetDefenderAbilitiesModifier()` 7577행(접촉 기술 0.5배), 메가루카리오Z 3칸 모두 파동의방호(`gen_4_families.h:4906`). upstream 1.17.1 #10777은 같은 번호 319로 이름 `Aura Guard`·설명 `Unimplemented.`만 넣고 효과는 없다. 효과는 upstream `upcoming`의 #10730(1.17.1 밖)에 있고 HnS 코드와 줄까지 같다.
- **upstream 1.17.1과 다른 HnS 고유 값 9개**(3절). 이 가운데 실제 동작이 다른 것은 **히드런(숨김 특성 칸)·대여르** 2개다. 나머지 7개는 빈 칸(`NONE`)을 같은 특성으로 채운 것이라 동작이 같다(빈 칸은 `GetAbilityBySpecies()`가 첫 번째로 채워진 칸으로 바꾼다).
- 1.17.0과 다르던 5개(앱솔Z·한카리아스Z·루카리오Z·갑주무사·드닐레이브)는 **1.17.1 #10777(Champions M-C)이 HnS 값과 같게 바꾼다** → 이 hunk는 HnS에서 변화 없음.
- 검증 범위: 소스 대조(코드/데이터 검증)만 했다. ROM 데이터 대조·실기는 하지 않았다(2026-09-19 기록에는 그때 ROM 99개 대조가 있다).
