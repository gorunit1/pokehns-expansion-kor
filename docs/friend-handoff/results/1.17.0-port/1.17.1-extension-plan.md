# full-sync 1.17.1 확장 계획 (2026-10-12, 계획만 — 이식하지 않음)

친구 요청 [`FRIEND_REPLY_2026-10-12.md`](../../FRIEND_REPLY_2026-10-12.md) 4절. 지금까지의 full-sync는 `expansion/1.17.0`(`e8bd1cd7b0`) 기준이고 순서표 [`port_sequence.tsv`](../1.17.0-sync-plan/port_sequence.tsv)는 seq 1~518이다(2026-10-12 현재 seq 285까지 끝, 다음 seq 287 #10415). 이 문서는 `expansion/1.17.0..expansion/1.17.1`(`bb1093a7c7`, 2026-09-29 "1.17.1 Release")의 PR 38개를 정리하고 1.17.0 순서표 뒤에 붙일 순서를 제안한다. **이번에는 이식하지 않았다.**

## 1. 결론

- **지금 목표는 1.17.0까지였다.** 1.17.1 PR은 순서표에 없고, #10837(편지 취소 assert)만 이식 전 동작을 되돌리려고 앞당겨 넣었다(`e804379040`, 묶음 11, 재확인 39). → 친구 방향대로 **최종 목표를 1.17.1로 넓힌다.** 1.17.0 순서(seq 287~518)는 그대로 끝내고, 그 뒤 **seq 519~556**에 1.17.1 PR 38개를 upstream 병합 순서로 붙인다(3절).
- **1.17.1은 확정 버전이다**(태그 2026-09-29). 38개 모두 공개·확정된 변경이다. 1.17.1 밖의 것(범위 밖, 기록만): upstream `master`의 1.17.1 뒤 커밋 9개(1.17.2 주기, 미발표), `upcoming`의 #10730(파동의방호 효과 — HnS 코드와 같음).
- **한글:** 1.17.1에는 **새 배틀 메시지(STRINGID)가 없다.** `src/battle_message.c`·`include/constants/battle_string_ids.h`·`src/strings.c`·`data/text/`·`charmap.txt` 변경이 0이다(`git diff --stat expansion/1.17.0 expansion/1.17.1 -- <파일>`). 그래서 친구가 정한 "새 배틀 메시지 번역"([`TRANSLATION_POLICY.md`](../../../localization/TRANSLATION_POLICY.md) 5절)은 1.17.1에 해당하는 문장이 없다. 대신 **출력 순서·선택이 바뀌는 PR**(#10698·#10788·#10829·#10839·#10843)은 이식 때 `BATTLE_MESSAGE_OUTPUT_CHANGES.md`에 적는다. 기존 텍스트 문맥을 건드리는 PR은 #10777(특성 이름·설명 — HnS 한글 유지)과 #10822(기술 설명 9개 줄 배치 — 내용 그대로)뿐이다.
- **세이브:** 세이브 구조 파일(`include/global.h`·`include/pokemon.h`·`include/save.h`·`src/save.c`·flag/var/종/도구/기술 상수) 변경이 0이다. 동작상 #10660(녹화 배틀 난수)만 이식 전 녹화본 재생에 영향이 있을 수 있다(친구 질문 Q2).
- **이미 들어간 것:** #10837 이미 적용(`e804379040`), #10816 HnS 동등(HnS 원래 커밋 `65388d7a`(2026-09-01)에 같은 수정). 둘 다 upstream diff 역적용이 깨끗하다.
- **HnS 선반영과 겹침:** #10777(Champions M-C)이 1.17.1에서 **`ABILITY_AURA_GUARD = 319`(HnS와 같은 번호)를 이름 `Aura Guard`·설명 `Unimplemented.`로만** 넣고, 메가 5개 특성(앱솔Z·한카리아스Z·루카리오Z·갑주무사·드닐레이브)을 **HnS 값과 같게** 바꾼다. → 상수·메가 hunk는 변화 없음, 이름·설명 hunk는 넣지 않고 HnS 한글 유지, 효과 코드는 1.17.1에 없다(HnS 2026-09-19 구현 유지). 메가 특성 전체 대조는 [`mega-abilities-check-2026-10-12.md`](mega-abilities-check-2026-10-12.md).
- **친구 질문 후보 2개, 알림 3개**(4절). 사용자가 혼자 정할 수 있는 것은 5절.

## 2. 조사 방법

- upstream: `../pokeemerald-expansion-upstream`, `git fetch --tags`로 `expansion/1.17.0` = `e8bd1cd7b0`, `expansion/1.17.1` = `bb1093a7c7` 확인. `git log --no-merges expansion/1.17.0..expansion/1.17.1` = 커밋 40개(PR 38개 + "Start of 1.17.1 cycle"·"1.17.1 Release").
- 크기: 이번 표만의 명시 기준 — S = 바뀐 줄 60 이하·파일 5개 이하, M = 400줄 이하, L = 2,000줄 이하, XL = 그 이상(1.17.0 순서표의 크기는 판단 기준이라 직접 비교하지 않는다).
- HnS 상태: 지금 HnS(HEAD `9aed68cb`)에 upstream diff를 `git apply --check`(정방향·역방향)로 대 보고, `git log`에서 `#PR` 이식 커밋을 찾았다. 정방향이 깨지는 것은 대부분 아직 이식하지 않은 1.17.0 PR 문맥이나 HnS 변경 때문이다(아래 의존 열).
- 1.17.0 순서표 의존: 각 PR이 바꾸는 줄(앞 이미지)을 부모 커밋에서 `git blame`해 그 줄을 마지막으로 바꾼 upstream PR을 찾고, 순서표에 있으면 표시했다. **굵게 = 아직 이식하지 않은 seq**(seq 287 이상이고 HnS 이식 커밋이 없음). 줄 단위 의존이라 뜻으로만 이어진 의존은 따로 적었다(메모 열).
- 저장소 밖 임시 스크립트로 만들었다. 다시 만들 때는 위 명령을 그대로 쓴다.
