## 사람이 결정할 사항 (D1~D6)

### D1. 일반 공격 빗나감 문장
- 지금 HnS:
  - 일반 빗나감: `그러나 {B_ATK_NAME_WITH_PREFIX}의\n공격은 빗나갔다!`
  - 변화기 빗나감: `{B_DEF_NAME_WITH_PREFIX}에게는\n맞지 않았다!`
- upstream은 ATTACKMISSED를 지운다. `resultmessage`는 PKMNEVADEDATTACK(한글 `…은(는)\n공격을 피했다!`)으로, `gMissStringIds[MISSED]`는 PKMNAVOIDEDATTACK으로 바뀐다.
- 선택지
  - A: 지금 그대로 둔다(HnS 전용 ID를 남긴다). #9939(seq 470)에서 다시 결정해야 한다.
  - B: upstream 그대로 따른다. `공격을 피했다`와 `맞지 않았다`가 섞인다. 비권장.
  - **C(권장)**: ATTACKMISSED를 지우고, HnS `resultmessage`에서만 PKMNAVOIDEDATTACK을 쓴다(1줄, `// HnS:`). 모든 빗나감이 기존 한글 `…에게는\n맞지 않았다!`로 통일된다. 새 번역이 필요 없고 #9939에도 그대로 이어진다.
  - D: C와 같은 결과를 EVADED 본문을 고쳐서 얻는다. 기존 문장을 고치는 것이라 별도 승인이 필요하다.

### D2. 점착·도구 뺏기 실패 (PKMNSXMADEYINEFFECTIVE)
- upstream은 이 ID의 의미를 "item cannot be removed"로 바꿨다. HnS 한글은 `{B_DEF}에게는\n효과가 없는 것 같다...`이고 점착·NoItemSteal·타오르는불꽃이 같이 쓴다.
- 선택지
  - **A(권장)**: 지금 그대로 둔다.
  - B: 새 문장(미결)을 쓰고 타오르는불꽃을 ITDOESNTAFFECT로 옮긴다.

### D3. 도주 특성으로 도망
- HnS는 `무사히 도망쳤다\p`이고 upstream은 `무사히 도망쳤다!\p`다(`!` 하나 차이).
- 선택지
  - **A(권장)**: HnS를 유지한다.
  - B: upstream을 따른다.

### D4. upstream이 바꾼 출력 17건을 한꺼번에 받아들일지

- 선택지
