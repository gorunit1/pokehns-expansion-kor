## 2. 꿈먹기 "효과가 없는 것 같다" 3번 (QA b4048-24) (`ad7fb887`)

### 원인 — 공통 처리 문제(꿈먹기 전용 아님), 포팅 누락

- `src/battle_move_resolution.c` `CancelerTargetFailure`의 대상 반복 6곳이 `battler < MAX_BATTLERS_COUNT`(4)였다. 대상 표시는 `gBattlersCount`(싱글 2)까지만 하므로, **싱글에서 없는 배틀러 2·3**이 건너뛰어지지 않고 "기술 효과로 영향 없음" 검사(`IsTargetUnaffectedByMoveEffect`)를 받았다.
- 이 검사에 걸리는 기술: **꿈먹기(대상이 잠들지 않음), 죽기살기(대상 HP ≤ 자신 HP), 싱크로노이즈(타입 불일치)**. 없는 배틀러마다 `BattleScript_ItDoesntAffectScrTarget`가 한 번씩 더 들어와 문장이 총 3번 나오고, 없는 배틀러의 이름은 빈 자리에 남은 데이터로 풀려서 틀린 이름("상대 한카리아스")이 나왔다.
- upstream **#10467**(`9ab8055a9e`, seq 441)이 이 6곳을 `gBattlersCount`로 고쳤는데, seq 441 이식(`d7b990b4`) 때 이 hunk를 "HnS 구조가 달라 해당 없음"으로 잘못 판단해 빼먹었다. → **포팅 누락(내 실수)**. `full-sync-seq-434-445.md`·재확인 90의 해당 문구를 정정함.
- 포팅 전 HnS(`c339f2b7`)에는 이 함수가 없었고(이전 구조) 해당 증상도 없었다 → 포팅으로 생긴 회귀.

### 수정

6곳을 `gBattlersCount`로(upstream #10467과 같은 내용). 출력을 숨기거나 횟수를 막는 방식 아님. 더블은 `gBattlersCount`가 4라 동작 같음.
