## 4. #9881(INCGFX)과 한글 폰트·이름 입력 화면

- 정정: 9881은 `graphics_file_rules.mk`를 **완전히 삭제하지 않는다.**
  - upstream 1.17.0에도 `graphics_file_rules.mk` 313줄과 `spritesheet_rules.mk` 25줄이 남아 있다. 여러 파일을 cat으로 합치는 규칙 등이다.
  - 폰트 규칙과 `FONTGFXDIR := graphics/fonts` 정의는 삭제된다.
- 한글 폰트 16개는 `data/fonts.s`의 **어셈블리 `.incbin`** 이 사용한다. INCGFX는 C 전용이다.
  - 따라서 `0d89762071`의 16개 규칙을 남은 `graphics_file_rules.mk`에 그대로 두고, `FONTGFXDIR` 정의를 HnS 폰트 블록에 다시 둔다.
- 이름 입력 화면 그림은 `src/graphics.c:2133-2136`의 `INCBIN_U8("…rwindow.4bpp")` 등이다.
  - `migrate_incgfx.py`로 `INCGFX_U8("graphics/naming_screen/rwindow.png", ".4bpp")`로 바꾼다. 전용 규칙이 없으므로 인자는 없다.
  - INCBIN과 일반 `%.4bpp` 규칙이 1.17.0에도 남아 있어서 그대로 둬도 빌드는 된다.
- HnS 전용 규칙은 migrate 스크립트를 **규칙을 지우기 전에** 돌려 INCGFX 인자로 옮긴다.
  - 대상: `spritesheet_rules.mk`의 HnS 규칙 약 2,200개와 HnS pokenav·타이틀·HoF 규칙
- 전후 산출물(`.4bpp`/`.gbapal`/`.smol`/`.lz`/`.latfont`)과 ROM 그래픽 구간을 바이트 비교한다.

## 5. #10429 ZWS(`0x3A`) 적응안

- `0x3A`는 HnS 한글 선두 바이트다(`src/korean.c:17`, 0x37~0x41). 그대로는 적용할 수 없다.
- 한글 후속 바이트는 0x01~0xEF 전체에 걸쳐 있다(239종). 0x00과 0xF0~0xFF는 모두 이미 사용 중이다. 그래서 **어떤 바이트와도 충돌하지 않는 단일 바이트는 없다.**
- 적응안:
  1. 선두 바이트 범위 밖이고 Latin 폰트 칸이 빈 자리(예: `0x42`. charmap에는 일본어 'ぢ'만 매핑)를 `CHAR_ZWS`로 쓰고, `ZWS = 42`를 추가한다.
  2. `RenderText`의 ZWS 건너뛰기는 비일본어 모드에서 단독 바이트로 읽힐 때만 적용한다. 후속 바이트는 기존 한글 결합 경로(`text.c:1587`)가 소비하므로 안전하다.
  3. `GetStringWidth`(1979, 후속 바이트를 이미 건너뜀)와 `GetGlyphWidth`에서 ZWS 폭을 0으로 한다.
  4. `line_break.c`의 `StripLineBreaks`와 단어 분할 루프를 한글 인식형으로 바꾼다. 선두 바이트 다음 바이트는 하이픈·ZWS·공백으로 판정하지 않는다.
- 전례가 있다. HnS는 `CHAR_NBSP`(0x39)가 선두 바이트와 겹치는 문제를 `battle_message.c:3797`에서 이미 예외 처리했다.
- 검증 항목:
  - 산출 문자열에 단독 `0x42`가 있는지 검사
  - 배틀 메시지 자동 줄바꿈(`battle_message.c:3829`) 회귀
  - 하이픈이 들어간 영문 문자열 표시

## 7. ROM·세이브 위험

### `7e7c38ab10`(`-ffunction-sections -fdata-sections`)의 영향

- 미사용 함수·데이터 삭제 PR의 ROM 절감은 **사실상 0**이 되었다. 대상: 10179(어제 -10KB 추정), 10152, 9911, 10184. `--gc-sections`가 이미 제거하기 때문이다. 이제는 소스 동기화 가치만 있다.
- 9231·9207의 RAM 절감은 유효하다. `EWRAM_DATA`/`COMMON_DATA`/`IWRAM_DATA`가 명시 섹션(`.sbss`/`common_data`/`.bss`)이라 개별 GC되지 않는다. EWRAM 약 -236B, IWRAM 약 -100B.
- 9086은 링커 스크립트 변경이다.
  - 문자열이 `.rodata.compound_string.<hash>` 명시 섹션(SHF_MERGE)에 들어가므로 `-fdata-sections`와 충돌하지 않는다.
  - HnS `.rodata`가 `*.o(.rodata*)`로 먼저 흡수하지 않도록 새 출력 섹션을 `.rodata` 앞에 둬야 한다.
  - 중복 병합 절감(추정 3~4KB)은 GC와 별개라 여전히 유효하다.
- Makefile·빌드 규칙을 바꾸는 PR 중 CFLAGS·LTO·`--gc-sections`를 건드리는 것은 없다(diff 전수 검색).
  - 9881: preproc/scaninc `-g`, `ASSETS_DIR_NAME`
  - 9721: learnset order-only
  - 9892: `TESTELF :=`, `map_data_rules.mk`의 `-s`, ld 공백
  - 10555: `json_data_rules.mk` 생성 규칙
  - 9724: 이미 계보에 있다.
